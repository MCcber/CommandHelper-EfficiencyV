# 数据包版本迁移设计（mcfunction / 数据包整体）

> 状态：设计稿，尚未实现
> 归属：CBHK 数据包生成器
> 关联资产：MinecraftLanguageServer 命令语法、misode `Command.json`、`Resource/Registries/*.json`、`Resource/vanilla-mcdoc/**`

---

## 1. 目标与非目标

**目标**

- 读入一个旧版本数据包，按用户选择的目标版本输出**可加载**的数据包：`.mcfunction` 内的命令、`.json` 内的资源字段、`pack.mcmeta` 的包元信息一并迁移。
- 迁移结果必须能被当前版本的解析器与 schema 校验器接受；**无法迁移的内容显式报告，而不是猜**。
- 版本差异全部来自资产（命令 schema / 注册表 / mcdoc），不在代码里写死版本分支。

**非目标**

- 不做"任意版本 → 任意版本"的语义等价保证：只保证语法合法 + 字段合法 + 可加载。
- 不迁移数据包之外的资源（材质、模型、音效文件二进制）。
- 不替代 `/reload` 之后的运行时行为验证。

---

## 2. 结论先行

"逐行监听 + 记录两个版本的 AST 路径 + 同类型 token 对齐"这个思路，**只适合做定位，不适合做决策**，需要两处修正：

1. **对齐按 ANTLR 规则 label / 参数名，不按 token 位置。** 目标版本在中间插入可选参数后，后续同类型 token 全部右移，位置对齐会把 `count=3` 配到组件参数上。
2. **版本变体的来源换成"每版本 schema"，而不是"两份 grammar 的树对比"。** 维护每个 MC 版本的 `.g4` fork 成本极高，而社区痛点的绝大多数是**值与结构变化**（NBT → components、附魔 map 化、id 改名），这些在 AST 形状上根本看不出来。

即：**一份 grammar 负责定位，每版本 schema 负责决策**，语法层只在 schema 表达不了时才做例外处理。

## 3. 可复用资产

| 资产 | 位置 | 迁移中的用途 |
| --- | --- | --- |
| 命令语法（ANTLR） | `MinecraftLanguageServer/MCFunctionRule/MCCommandLexer.g4`、`MCCommandParser.g4` | L1 解析定位，产出参数名与 span |
| 命令 schema（计划接入） | `Resource/Configs/Command/Command.json`（按版本一份） | L2 判定参数增删改、默认值候选 |
| 注册表差异 | `Resource/Registries/<version>.json` | L2 值域映射（物品/方块/实体/附魔/属性等 id 改名） |
| SNBT / 组件形状 | `Resource/vanilla-mcdoc/java/**`（如 `data/recipe.mcdoc` 的 `since/until`） | L2/L3 结构改形规则 |
| 门禁探针 | `CBHK.Probe`（`--gate` 系列） | 迁移结果的自动化验收 |
| 策略 + 注册器范式 | `IRecipeStrategy`/`ISlotDropStrategy` 及其注册器 | L3 值迁移器的组织方式 |

## 4. 设计原则

1. **单一真源**：版本、字段、id 的差异只能来自资产；代码里出现写死的版本号或类型串即视为缺陷。
2. **默认值不猜**：语法不携带语义。默认值必须来自 `Command.json` 的显式声明或人工维护的默认值表；推不出来就**拒迁该行并报告**。
3. **逐行原子、可加载优先**：一行要么整体迁移成功并通过目标语法复查，要么**逐字节原样保留**并在报告里登记，绝不输出"改了一半的行"。
   写出前还有一道**目标语法门**：文件内每一行都必须能被目标版本解析——无法迁移且目标语法不认的行，按策略**注释掉并打标记**（`# MIGRATION-BLOCKED <原因> | <原文>`），保证整份 function 文件仍可加载；不再因为一行而整份文件作废。
4. **最小替换**：只替换需要变的 span，其余字符原样保留，便于用 diff 审阅与 git 追踪。
5. **幂等**：源版本 == 目标版本时，输出必须与输入逐字节一致。

## 5. 分层架构

```
                ┌──────────────────────────────────────────┐
输入 .mcfunction │ L1 语法定位（ANTLR listener）             │
                │    CommandNode { path, args[(name,span,raw)] }
                └───────────────┬──────────────────────────┘
                                │
       源版本 ---------------→ ┌▼─────────────────────────┐
       目标版本 --------------→│ L2 规则集（版本差 → 规则） │
       Command.json ---------→│  Rename/Retype/Insert/... │
       Registries -----------→│  仅对命中的 path+arg 生效  │
       vanilla-mcdoc --------→└───────────────┬──────────┘
                                              │
                                ┌─────────────▼────────────┐
                                │ L3 值迁移器（按数据域）    │
                                │  item-components / block- │
                                │  state / entity-nbt /     │
                                │  enchant / attribute ...  │
                                └─────────────┬────────────┘
                                              │
                                ┌─────────────▼────────────────────┐
                                │ L4 回写 + 复查                    │
                                │  最小 span 替换 → 重新 parse      │
                                │  → schema 校验 → 通过才写文件      │
                                └──────────────────────────────────┘
```

- **L1**：一行一条命令；解析失败不抛异常，产出 `UnparsedLine` 并继续。
- **L2**：规则集在迁移开始前**只计算一次**（版本差），不要逐行重复 diff。
- **L3**：每个数据域一个 `IValueMigrator`，注册进 `ValueMigratorRegistry`；新增版本只加规则数据，不加分支代码。
- **L4**：迁移后的文本必须重新走 L1 解析 + schema 校验，失败即**回滚该行**（恢复原文）并登记；文件级只做一件事——把目标语法不认的行注释成 `# MIGRATION-BLOCKED`，使整份文件保持可加载。

---

## 6. 规则模型

| 规则 | 语义 | 数据来源 | 示例 |
| --- | --- | --- | --- |
| `RenameArgument` | 参数改名 | Command.json（源/目标参数表） | `Count` → `count` |
| `RetypeArgument` | 参数类型变化 | Command.json + mcdoc | NBT 对象 → components 对象 |
| `InsertDefault` | 新增必填参数补默认值 | 默认值表（人工维护） | `/execute if` 新增子命令 |
| `RemoveArgument` | 参数被移除 | Command.json | 旧字段被组件取代后删除 |
| `ValueMap` | 值域改名 | Registries 键差集 | `minecraft:grass` → `minecraft:short_grass` |
| `ReshapeSnbt` | SNBT 结构改形 | mcdoc `since/until` | `{item:"x",Count:1b}` → `{id:"x",count:1}` |

规则命中判定一律以 `(命令路径, 参数名)` 为键，禁止按索引定位。

## 7. 源版本识别

1. 读数据包根 `pack.mcmeta`：
   - `pack_format`（1.20.2+ 还可能有 `supported_formats`）；
   - 通过 `pack_format ↔ 版本` 映射表换算成版本号（映射表随资产维护，不写死在逻辑里）。
2. 缺失或无法识别时，回退到用户在界面上选择的"源版本"，并在报告里标注"版本由用户指定"。
3. `.mcfunction` 自身不携带版本信息，不得尝试从内容推断。

---

## 8. 行级容错

必须原样保留且标注"未迁移"的情形：

- 空行、行尾空白、`#` 注释行；
- 宏行（`$(...)`，1.20.2+ 函数宏）；
- 解析失败的行；
- 指向本地自定义函数的调用（`function <ns>:<name>`），只做命名空间/路径校验，不改写；
- 多行 SNBT（若存在）——当前 mcfunction 不允许跨行，检测到即报错并跳过整条命令。

---

## 9. 最小可交付切片（M1）

- **命令集**：`/give`、`/summon`、`/data`、`/item`、`/execute`（覆盖组件迁移主要痛点）。
- **版本对**：`1.20.4 → 1.21.5`。
- **输入范围**：纯 SNBT，不含宏行。
- **语料**：30~50 条 golden 对（旧文本 → 期望文本），进 `CBHK.Probe` 作为门禁。
- **对外可引用的数字**：`1.20.4 的 give/summon/item 语法，X% 的行可自动迁移，产物 0 条不合法`。

---

## 10. 验收门禁

| 编号 | 不变量 | 检查方式 |
| --- | --- | --- |
| G1 | 幂等：源版本 == 目标版本时输出逐字节等于输入 | golden 用例 + 字节比对 |
| G2 | 合法性：迁移产物通过 L1 解析与 schema 校验 | `CBHK.Probe --gate migrate` |
| G3 | 无静默丢弃：每条无法迁移的行都必须进报告；写出的 `.mcfunction` 内**每一行都通过目标语法解析**（`# MIGRATION-BLOCKED` 注释行除外） | 断言报告条目数 + 逐行目标语法解析 |
| G3b | 可加载性：迁移后每个 function 文件在目标版本下可完整加载 | 目标版本解析器整文件解析（模拟 `/function` 的加载行为） |
| G4 | 最小替换：除命中规则的 span 外，输出与输入逐字节一致 | 结构化 diff |
| G5 | 无硬编码：迁移代码中不出现具体版本号/类型串 | 源码扫描（沿用现有 grep 式门禁） |

## 11. 包级迁移范围

| 对象 | 处理 |
| --- | --- |
| `pack.mcmeta` | `pack_format`/`supported_formats` 改写为目标版本 |
| `data/**/function/*.mcfunction` | 走 L1~L4 主流程 |
| `data/**/{advancement,loot_table,predicate,item_modifier,recipe,...}.json` | 走 schema 字段迁移（与配方模块的版本化生成共用同一套规则来源） |
| `data/**/tags/*.json` | 只做值域改名与目录校验 |
| `assets/**` | 不动，仅报告版本相关的模型/材质失效项 |

输出目录约定：`<pkg>/<ns>/...` 原样结构，另在根目录写 `migrate.report.json`（每文件一节的统计与失败明细）。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 每版本 schema 缺失或滞后 | 规则集不全，迁移漏项 | 以"拒迁 + 报告"兜底；schema 版本号写进报告，便于复现 |
| 默认值猜错 | 产出能解析但语义错的命令 | 默认值一律查表；表中无值即拒迁（G3） |
| grammar 与目标版本不匹配 | 解析失败率上升 | grammar 只做定位，允许"解析失败但可报告"；必要时才引入按版本 grammar（预算为例外） |
| 值域映射不全（id 改名） | 迁移后引用不存在的 id | 用 Registries 做**存在性校验**，缺项进报告 |
| 宏行/跨行 SNBT | 解析异常 | 明确不支持并显式报告，不尝试启发式修复 |
| 半迁移（同一 id 有的行改了、有的行没改） | 包看似已迁移，实为混用两版语义 | 包级一致性检查：同一次迁移中，`ValueMap` 的旧值不得在新值已出现的包里残留；违例进报告并阻断该包的"已迁移"状态 |
| 第三方语法/schema 许可 | 分发合规 | 资产来源与许可证登记进"关于"页，随包附 LICENSE |
