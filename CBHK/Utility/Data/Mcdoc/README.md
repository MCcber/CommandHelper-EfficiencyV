# Mcdoc 树渲染管线：业务模型与踩坑备忘

> 只写两件事：「业务怎么理解」（含两个视图必须同时成立的契约）、「哪里容易踩坑」。
> 不写功能清单、不写实现方案、不写进度、不写待办、不写实测数字、不写文件目录 —— 做完的事不进这份文档，只有踩过的坑留下来。

## 一、术语速查

| 词 | 含义 |
|---|---|
| dispatcher | mcdoc 的 `minecraft:resource[<registry>]`：按资源 id 落到具体 schema。本项目拿它当"页面入口" |
| EntryId | 页面传入的 dispatcher id（如 `dimension_type`），生成器页面的唯一参数 |
| spread | `...SomeType`：把另一个结构的字段摊平进来，simplify 阶段落地 |
| `#[id]` | 字段值的取值来源标注（registry / tags / include / exclude / prefix），决定下拉候选 |
| 判别键（必选 Enum） | 决定同层 dispatcher/spread 解成哪一支的必填字段；界面上是下拉，候选来自 `#[id]` 的注册表/调度器空间 |
| 物化 / 不动点 | 把行上已显示、文档里没有的必填值写进 JSON，再整篇重解；重复到某一轮不写任何键（上限 3 轮） |
| union / unset | 联合类型；下拉里的"（未设置）"哨兵表示**删掉这个键** |
| inline tuple | ≤4 且全数值的元组，一行内渲染完，不产子行 |
| Head / Row | Head 是 presenter 产出的"这行怎么画、能点哪些按钮"；Row 是投影出来的扁平行对象 |
| 懒建 | 子级到展开时才建（`EnsureChildren`），默认展开深度 3 |
| NF / 指令 | 归一形态 vs 求值指令（Reference/Concrete/Template/Mapped/Indexed/Dispatcher），见 §二 |
| RebuildAnchor | 最近的容器祖先：运行期依赖变化时"从哪一层重建" |
| 键身份 | 一条 entry 在 JSON 里的位置：`FieldName` + `JsonPath` + `KeyNode`(`RuntimeKey`)。`%key` 类动态索引全靠它 |

## 二、求解模型：混合结构怎么归一

### 2.1 归一形态（NF）

引擎里"能被渲染 / 被索引 / 被合并"的只有：

`Any / Boolean / String / 数值 / Literal / Enum / Struct / Union / List / Tuple / 字节数组`

其余六种是**求值指令**，必须在求值期消掉、不许出现在节点上：

`Reference / Concrete / Template / Mapped / Indexed / Dispatcher`

### 2.2 两个上下文

| 上下文 | 作用 | 生命周期 |
|---|---|---|
| `TypeArgs` | 排队中的类型实参，只被"下一个 Template / 泛型 Dispatcher"消费一次 | `Concrete` 写入 → 被消费后清空 |
| `TypeMapping` | 形参→类型的替换环境；结构体字段以 `Mapped{copy}` 自带环境（唯一惰性边界） | Template/Mapped 写入，可继承 |

规则：**任何指令都不许丢弃它不消费的上下文**。

### 2.3 指令消去规则

| 指令 | 规则 |
|---|---|
| Reference | 命中 `TypeMapping` → 直接替换；否则按"声明模块 + use 别名 + 祖先模块"解析后**带同一上下文**继续 |
| Concrete | 实参先按当前上下文求值 → 写入 `TypeArgs` → 求值 Item（保留 `TypeMapping`）；**实参带动态索引时保留声明、不在此求值**，由消费方在自己的节点上求值 |
| Template | `TypeArgs` → `Mapping`（外层为底、内层覆盖；缺省 `any`）→ 清 `TypeArgs` → 求值 body |
| Mapped | 合并 mapping（外层为底、内层覆盖）→ 求值 Item |
| Indexed | **带同一上下文**求值 child（不清 `TypeArgs`）→ 按索引代数作用在 NF 上；无索引时等价恒等 |
| Dispatcher | 解析成员目标；`TypeParams` 非空时用当前实参替换后再求值 |

### 2.4 索引代数（定义域 = 全部 NF）

| 被索引的 NF | 语义 |
|---|---|
| Struct | 按字段名 / 动态键（`Tuple[键,值]`）取类型；未命中走 `%unknown` / fallback |
| Union | 逐成员索引后取**并集**（去重保序，非 struct 成员跳过并报告，上限 64，全失败才 `any`） |
| Tuple | 静态下标取项；动态索引对所有项求值后并集；越界 → `any` |
| List | 取 `Item` |
| Any | `any` |
| 其它 | `any` + 诊断（可见，不静默） |

### 2.5 节点边界与诊断

- 工厂求值后若仍是指令 → **换成 `any` + 保留诊断**（"未解开的类型包装：X"）。渲染层因此只看到 NF：Struct/Union 永远不会是 Text/Raw，`any` 是唯一 Raw 兜底且**必须带诊断**。
- 求值期的诊断（引用解不开 / 未知调度器 / 不可索引 / 联合成员未解出）统一挂到行的 `Error` 上。
- 空联合 `()`（文档里真的声明成空）是合法 NF，单独给"存在性谓词"诊断。

### 2.6 两条容易被忘的语义

- **spread 的 union 语义**：`...U`（U 是 union）合并所有 struct 成员的字段；非 struct 成员报告跳过；一个都没合并时补"未知字段"占位。
- **mapping 合并**：`Template`/`Mapped` 的映射以外层为底、内层覆盖，模板体里引用外层形参不丢键。

### 2.7 一份文档、两个视图：必须同时成立的契约

用户只看得见"左边树、右边文本、和一份文档"，所以这些不是"测试断言"，而是这个编辑器对用户承诺的东西：

| 契约 | 含义（用户视角） |
|---|---|
| 文本单个根 | 右边的文本永远是一份合法 JSON。语法错误期间树冻结、**程序不替你改文本**；但你一旦在左侧动了树，就要把脏区域对齐成合法文本 |
| 视图同代 | 屏幕上文本 = 模型里的文本，不能一个改了另一个没跟上 |
| AST 同源 | 树的节点与文本共用同一批对象，否则"树上的编辑永远进不了文本" |
| 行 → 文档 | 一行显示的值就是文档里该路径的值；**比"值"不比"对象身份"**（整篇重排会重建对象） |
| 无孤儿行 | 每一行都能挂到一个存在的父行上 |
| 缩进契约 | 子行必须比父行深（缺省/压缩层可以跳，但绝不许同层） |
| 缺省字段不摊开 | 文档里没有的可选字段只有一行 ⊕，不许挂子级 |
| 键 ↔ 行双射 | 文档里每个键都有对应行，且只有一行。**例外**：当前版本不存在的键（`IsUnknownField`）只出**一行**，它里面的子键不出行 |
| 无重复键 | 同一个对象里不许出现两个同名键 |
| 导出 = 屏幕 | 复制/保存出来的就是屏幕上那份文本 |
| 换版本不改文档 | 切游戏版本只换 schema 求值口径，不许动用户已经写的键值 |
| 会话干净 | 关窗体再开是干净的一份默认文档（折叠态、未消化输入都不许带过来） |
| 树侧操作 × 右侧语法错误 | 定位"能包含住脏区域的最小完整结构"，用左侧模型的同一份整段替换 → 严格解析验收 → 整篇写回 → 排版；定位不到就一个字符都不改（不猜 `}`、不补引号） |
| 输入即文本 | 用户粘进右侧的内容必须被当成输入：**看不见的空白（BOM / 不换行空格 / 零宽空格 / 全角空格）先归一成普通空格再解析**，否则"看着合法的 JSON"会被判语法错误、树按契约冻死 |

## 三、踩坑清单（都真踩过）

- **非法形状必须给"诚实的形状"**：声明/求值是容器却拿到标量（或反过来）时，节点一律降级成 `any` + 错误诊断（`值与类型不符：期望 X，实际 Y`），**绝不按声明类型摊开子级**，否则会长出"父是字符串、子却在展开"的幽灵行。子级继承同样钉死：父 JSON 不是 Object 时 `fieldJson` 必须是 null。**容器之间也会错配**（声明 struct、文档是数组）—— 根上一份函数数组配上 struct 声明时，声明字段照样成行，用户看到的是"树上一堆字段、右侧一份数组，干啥都对不上"，所以"结构要对象、列表/元组/原始数组要数组"要一起判。
- **行与文档比"值"，不比"对象身份"**：一次整篇重排会重建对象，引用相等不是用户看得见的契约；"行的值 = 文档里该路径的值"必须内容比较（"行有值、文档没有"的缓存残骸照样要红）。真正的身份契约只在"树节点与编辑器共用同一批 AST"那条上守。
- **跨资源存在性只给 warn**：字段带 `#[id=<registry>]` 且值不在注册表里 → 行上挂 warn（不 error、不改值、不弹选择）。拿不到注册表数据时**不判**，但要在 trace 里说清楚，别把"没验过"当成"验过了"。也**不许为了"让它显示出来"回写选择**。判定要走实例级缓存，id 空间不许跨实例/跨版本串。
- **归一化（空白类字符）必须挂在那条"真正被粘贴走到"的出口上**：粘贴走的是编辑器文本变更 → 防抖 → `SyncTextToTree`；只挂在"树→文本"或"换版本载入"上等于没挂 —— 现象照旧，日志里也一条记录都不会有（"改了没生效"的第一手证据就是日志有没有走到）。
- **物化（把行上显示的值落盘）必须跑到「不动点」，而且每条重建路径都要跑**：物化写一个键就会重建文档，重建又让派发器/动态索引解出新的必填字段（`type_specific.type` → `...entity_sub_predicate[[type]]` → `BoatPredicate.variant`）。只跑一轮的结果是"行上显示 Oak、文档里没有 variant"，依赖它的下游索引永远停在未求解。
- **必填容器没建出来，里面的必填字段永远物化不到**：物化只走"已经建出来的子节点"，而结构表现器在 `json == null` 时直接返回 —— "必填结构 → 必选枚举"这种两层必填链，里层连节点都没有，校验就一直报"缺少必填键"。物化第一步要先把**必填容器的空壳**补上，再靠不动点把下一层带出来。
- **判别键的三种"没有值"是同一个意思**：缺键 / `null` / 空串，`...dispatch[[type]]` 三种都会读成 `%none`，同层 spread 一个成员都解不出。收口不是刷新子行：**父级按新 JSON 整篇重解**并物化到不动点；父级自己的 `Indices` 是空的，索引挂在 spread 字段上。
- **判别键必须在"第一次求值之前"按声明写进 JSON**：等求值完再写就晚了（`[[type]]` 已判成 `%none`，闭合候选一起丢）。判别键常被 Union/Mapped/Concrete/Template 包着，按已求值结构找会漏。候选必须走 `#[id]` 的 id 空间出口：拿一次性演示节点去问渲染层，在 union 标量支上会静默拿不到候选。
- **判别键预写要把空串当成"没有值"**：默认值代数对必填字符串给的是 `""`，把它当"有值"就会静默跳过预写。物化那条出口早就把空串算作没有值，两条口径必须一致。
- **"行上显示了默认值"不等于"JSON 里有这个值"**：必填 + 白名单闭合下拉会自动选中第一个候选但建树期不落盘；依赖它的动态 spread 会解析成 `%none`（`advancement.criteria.<name>.trigger` 的子级整片空）。只对**必填**字段物化默认选中值；重建/切支新长出来的子树还没有行，"显示中的候选"要按候选表首项落盘。
- **候选下拉行的空文本绝不许落成 `""`**：`block: ""` 进了文档 → `#[id]` 行立刻挂"值不在候选内"，靠它做动态索引的 `properties` 整片解不出来。文本编辑只在**没有候选**时才允许空串；空值优先落"行上显示的候选"（真 unset 走哨兵分支，不靠清空编辑器）；物化把"键在、值是空串"也算没有值。
- **物化写成员不能用纯追加**：父对象里常有同名的空值（`trigger: ""`），追加后成两个同名键，dispatcher 读第一个 → spread 依旧空，行上却"已选中候选"。新建祖先容器键也要按声明序插入。
- **物化的容器不许"往上找最近有 JSON 的祖先"**：那是把子键提到根上的唯一通道（删 `display` 却出现 `{ "title": "x" }`）。只有 union 摊平出来的分支层可以借容器。
- **依赖键换掉之后，靠它求值的子树必须"重新求值"而不是"刷新"**：`dispatcher`/`indexed` 在兄弟键还没有值的时候只能解成兜底 `any`，刷新只是重跑表现器、用的还是建节点那一刻的兜底类型 —— "第一次是哑的、折叠再展开才好"。值变更后要按**声明**找出用这个键做动态索引的兄弟走重建；兄弟之外还有**父级**（`...dispatch[[key]]` 的 spread 挂在父结构上），顺序先兄弟、最后父级。
- **判别键的宿主会被 union 摊平**：Object 支的字段行直接挂在 union 行下（`Parent` 是 union、连文档根都可能是它）。按 `DeclaredType` 找 spread 是找不到的（union 上没有 `Fields`），而且根 union 没有父级 —— 判据必须按**生效结构**（union 当前选中的结构成员）判"这一层是否按该键做动态索引"，并允许 union 自己作为重建目标。
- **真 schema 的根 dispatcher 要单独兜底**：predicate 的根节点 `DeclaredType` 是 `Dispatcher`，声明链上找不到 `LootCondition` 里的 spread；只按声明判会得到"父级不依赖这个键" → 切 `condition` 后 `block` 不出现、旧 `terms` 不剪。兜底判据是"父级读过运行期数据 **且** 当前行有候选表"；普通数字/纯文本没有候选表，不能走这条，否则每敲一字都会重建父级、丢焦点。
- **含动态索引的泛型实参延后求值时，必须先把外层泛型映射替换进实参**：`NonEmptyWeightedList<IntProvider<T>>` 的实参若带 `[[type]]`，延后到 `data` 节点求值时，里面那个 `Reference T` 会解成 `Any`，min/max 退化成 Any 类型下拉。只做引用替换（`SubstituteReferences`），不要直接存原参，也不要用 `Mapped` 包一层。
- **"靠这个键解出来的兄弟"要重建，诊断也要按节点重算**：值补丁只改 `node.Json`，整树校验不会跑 —— "JSON 里改回合法值，行上的感叹号去不掉"。补丁后按节点重算一次校验，并把它在文档级清单里的旧条目换掉。
- **依赖键把某层的类型换掉时，那一层的值要跟着整形**：`argument` 的类型由 `float` 变成结构、文档里却还留着 `6` → 行上只能挂"值与类型不符"。判据要用**按声明重新求值**出来的类型（节点上的 `Type` 在值不符时已降级成 `any`，拿它判"值仍然成立"恒真）；整形要放在所有重建之后，且 `X→{k:X}` 要自己搬（通用搬运不跨数值 kind）。
- **派生容器"解不出任何成员"时必须退回"没有值"**：`Properties`（`mcdoc:block_states[[block]]`）的 ⊕ 判据是 `Json == null`；切成无属性方块后只把子键剪掉、把 `{}` 留在文档里，行上既没有子行、⊕ 又灰着 —— 展开了再切过去就"点不动"。剪键要**当场把对应子节点从三个子级集合里摘掉**（只置"子级未建"的标记靠不住）；父级重建后再按**声明**扫一遍字段：可选 + 声明是调度器/索引 + 按当前上下文求值后零字段 + 值确实是空对象 → 删键。这条判据不能走"已建好的子级"（那一拍父级的子级还没建）。
- **派生容器的 ⊕ 也不能把空 `{}` 写进文档**：无属性方块上点 Properties 的 ⊕ 若落了 `{}`，切回有属性方块后 `Json` 已非空、⊕ 判据失效，用户看到"添加按钮没反应"。`SetDefault` 先按声明解析：派生容器解出零字段结构时直接 no-op；普通空结构仍允许写 `{}`。
- **JSON 写入/删除必须通知行重算摘要**：`McdocTreeNode.Json` 的 setter 要抬 `PropertyChanged(nameof(Json))`，行上只做 `RefreshDiagnosticsOnly`（重算按钮可见性与摘要，不重发 Kind/Head）。否则 ⊕ 已经执行、子结构也出来了，按钮还停在"添加且不可用"。
- **SetDefault 执行后要整表对账投影**：WPF 行容器在局部 Splice 后可能继续复用旧 Head（子结构已出现、按钮仍是禁用的添加；改一次子值触发 Reset 才恢复）。执行完先在行上 `RefreshHead`，再整表 Reset，不能只依赖父级的局部拼接。
- **运行期依赖父级的结构添加不能只排延后重建**：`Properties` 的 ⊕、map 条目、列表新项等结构手势，先把当前这一层 `EnsureChildren` + `RefreshAround` 拼进投影，再排延后重建做类型校正；只排延后的话，用户点完 ⊕ 看到的是一行没有子结构的 Properties，必须手动折叠/展开一次才出来。
- **派生容器被摘掉 / 父级重建后，投影必须整表对账，不能只 `RefreshAround`**：嵌套 list/union 的已展开子树里，局部拼接不保证覆盖，行会继续指着旧节点。父级重建或摘掉东西时，物化结束后统一整表 Reset；只有"只重建兄弟依赖"时才保留局部拼接。用手动 Reset 再断言的测试会掩盖这条。
- **切支只把值换成新支的形状，分支还要"按新对象再解一拍"**：切支会把 union 的 `Json` 换成**新对象**，而分支节点是按**旧对象**建的 —— List 支切 Object 支之后，同层 spread 读到的还是上一支的 JSON（只剩判别键一行），手动再触发一次重建才会好。收尾要按当前文档连做两次定向重建。
- **切分支必须发一条值通知，而且只能发一条**：剪旧键 / 补新支默认结构 / 值转换都会改文档，但"形状没变"时转换会早退，于是整段切换一个字节都没告诉宿主 —— 右侧停在 `{}`、行停在上一支。重复发会让重建排两遍。
- **切分支要丢掉"旧成员声明、新成员不声明"的键**：结构分支的字段行是上提到 union 节点上的，那些键留在文档里 → 切完 `terms` 还和 `block` 并排出现在行上。剪枝要在把值转成新分支之前，按"求值成员的字段集合"做差集，且只对"旧新都是结构"生效（标量/列表/any 成员没有静态字段，剪下去会把要搬运的旧值先吃光）。
- **切成员 = 清旧成员的键，但"值仍成立"的用户数据要留**：新成员不声明的键一律删；两边都声明的键，值在新声明下不成立才删（旧成员 `x: int` 带到新成员 `x: string`、方块 A 的 `facing` 落到方块 B 上）。"保留旧键"只属于**换游戏版本**那条路径。
- **剪键只有一条规则，但有两个入口**：union 走"重置选中分支"，依赖键（方块 / 枚举成员）走"清派生成员"；两个入口都要在"切换这一件事"上调用（只在切换里调、程序化 setter 不调，就会留下旧成员的键）。
- **分支子树必须建在文档里那份值上**：建树期走"值转换"等于把分支子树建在"新成员的默认值"上，文档里那份 JSON 一个字段都没传下去，靠同级键的动态索引在分支内部全部取不到键。值转换只在用户真的换分支时用。
- **值转换的四条搬运规则靠"旧类型 = 切走的那个成员"，不是 union 声明**：`X→[X]`、`[X]→X`、`X→{k:X}`、`{k:X}→X` 都要求"旧成员类型 ~ 新成员类型"；把 union 声明当旧类型传进去，这四条永远不会成立。
- **"形状相同就不动"要配一条"值落不进这一支"**：只按"是不是对象/数组"判，`[int]` 切到 `[string]` 支会把 `[1,2,3]` 原样留下（行上一条条"值与类型不符"）。判据连条目类型、tuple 项数、`#[length]` 区间一起判：落得进就一个字不改，落不进才把转换结果落盘。
- **union 标量支的"空值"不是 unset**：切到 `string` 支时转换写出来的是 `""`，回写出口若按"可选字符串清空 = 删键"处理，就把**分支身份**一起删了，下次重建只能回到未设置（"选了 String 分支立刻弹回"）。unset 只走下拉里的（未设置）。
- **union 选「未设置」不等于只删键**：删键之外还得清**分支镜像**（标量编辑器种类 / 候选表 / 选中项 / 列表支镜像 / 是否闭合下拉）、清分支子级、折叠，并且**返回"真的变了"**让行重投影。少任何一步，行上就留一个写着旧值、点不动的死编辑器。
- **条目的（未设置）必须"先清镜像、再发值通知"**：只删键时分支镜像还挂着，宿主收到值通知会按"这不是结构分支"把旧值写回文档，键当场又回来。顺序钉死：静默删键 → 清镜像 → 最后发一次值通知。
- **同值能匹配多个 union 成员时，按"具体程度"选支**：`"black"` 同时命中"枚举支"和"字符串支"时，多命中就放弃会让每次重建都把枚举支打回字符串。具体度：字面量 > 枚举 > 普通同型 > `any`，并列最高仍不猜。
- **union 选默认分支时 `any` 成员不许压掉结构支**：`any` 匹配一切但具体度最低；"精确匹配"阶段它会胜出（结构支因缺必填键判不匹配），于是"对象被当 int 渲染 / 切过去就弹回"。兜底按 JSON 形状重挑，且**只作用于显示层**。
- **union 行的分支列表不许是 null**：空联合 `()` 是合法 NF，给 null 会让行上的"取第一个分支"直接抛。
- **解不出来的 union 成员不许粘在选择上**：声明不是 `any`、求值却退成 `any` 的分支切过去要**立刻回 unset + 挂诊断**，否则行上留一个"看着有编辑器、其实写不出合法值"的死分支。判据用**声明形态 vs 求值形态**，不许按名字特判。
- **`#[id]` 候选必须过版本过滤**：调度器成员带 `#[until=…]` 这类标注时成员表仍会列出它，候选不过滤就会让人选到"求解期会被滤掉"的键（spread 解不出、只剩一条诊断，且切走再切回也不会自愈）。判别键物化取候选同样要过版本门控；`#[id(..., tags="required")]` 的候选只能是 tag。**按声明找判别键宿主也要过版本门控**，否则旧版本成员会被当必填字段预写回 JSON（删掉的遗留键又长回来）。
- **当前版本不存在的键只出一行、不解析子树**：走专门的"遗留键"表现器（不建子级、不给编辑器），行尾只留黄色 `!`；文档里那份值原样留着（"换版本不改文档"）。三条硬约束：① 未声明键必须在建节点时就打标记且 `IsRequired = false`（否则一个都删不掉）；② 标记必须在建节点之前/当下打上，事后已经晚了；③ 行尾不再挂诊断徽标与删除按钮。删除入口分两条路，落点都必须是**活文档**：键还在 → 按 `JsonPath` 解析活父容器删键；键已经不在（残影行）→ 从活父级摘掉这一行再重拼；缓存的 `Parent` 可能是上一代节点/union 分支壳，拿它动手会"闪一下又回来"。活父级解析不到时宁可整篇重载。**不能**走父级重建（同一父级下其它幽灵行会被一起清走）。
- **幽灵行（键已经不在文档里、行还挂着值）必须有删除入口**：切 union 剪键 / 右侧删键之后投影没跟上的那一行，常规四个出口**全都不成立** —— 用户看到"左右两侧都不存在的节点怎么都删不掉"。判据是"父级对象里没有这个键"，并入遗留键的删除可见性。
- **"键被删掉"必须折叠，投影侧也要兜底**：可选字段的 `Json` 变成 null 时，节点若还留着展开状态，投影会把**早就建好的子级**重新摊到行下面。值变 null 且非必选时立刻折叠；投影对"可选 + 没有 JSON"的节点直接不拼子级。
- **值是 null 之后，子级要放开**：删字段会把"子级已建"冻结，再 ⊕ 时 `{}` 回来了但子行回不来（"结构有了、行没回来"）。删字段要连 `node.Json` 一起断，否则残留值会被后续物化/回写当成"还在文档里"。
- **折叠态是静态表，必须按"页面实例"分会话**：只按 EntryId 分会话时，关窗体再开会把上一个窗口的展开态带进来 —— "文档里根本没有的字段"被撑开、子行凭空出现，父行还是个 ⊕，看着像"子结构摊到了同层"。会话键 = (EntryId, 页面实例)；`json == null` 的字段一律只留一行 ⊕。
- **"添加之后要展开"必须只有一条规则，且新节点按路径预约展开态**：新条目/新列表项在那一刻还没有节点（要等父级重建），必须先按**路径**记下"展开"，再抬结构变更。列表自己的展开态也要在结构变更之前预约，否则新实例按"默认折叠"建出来，新项行永远不出现。
- **"加一项"不许有第二条路**：列表行的 ⊕、"在顶部新增"、尾部"追加"行若各写一遍默认值与守卫，只有其中一条会做"揭示新项 + 预约展开态"，于是"点 ⊕，右侧多了一条、左侧树一动不动"。
- **列表项的"复制这一项"也是添加手势**：通知要发给列表（不是被复制项），并同样预约新项/列表的展开态；只刷被复制项就是"右侧多一项、左侧没有行"。
- **记住的展开态不许再按"有没有子级"拦**：建节点这一拍"有没有子级"可能是 false（数组刚写进去、子级还没建），拦下来就是"记住要展开、节点却是折叠的"。只留"文档里有没有值"这一条守卫。
- **懒建节点展开必须先 `EnsureChildren`**：展开走的是"只拼这一行子树"的捷径，不经过初次投影那条路；漏了这一步，深度 ≥ 3 的节点点箭头只会得到 0 行。同时要给出"刚建出子级"的钩子。
- **缺省成员不许在"饿建期"把子结构建出来**：关掉懒建时，"有父级 && 没有 JSON"这类守卫恒为 false（父级只在子级建完之后才赋值 `Parent`），于是缺省的可选成员照样把整棵子树建出来，而投影对这类节点一列子行都不画 → "节点建出来却不可见"。要由**父级**在创建子级时说清"这是缺省成员"（必填成员不 defer）。
- **"必选 + 缺值"的容器行是死行，除非三件事都做到**：① 空壳要补出来，且判据必须**看穿声明包装**（声明常被 `Mapped` 这类指令包着）；② 必选缺值也要摊开子级（"没有 JSON 就早退"只对**可选**成立）；③ 展开箭头要真的能点出东西。三条缺一条，用户面前就是"Argument 展开失败"。
- **展开箭头的判据用「真的建出了子级」**：已建就数子级个数，没建才按能力预测。按类型猜能让有子级的行没箭头、空容器挂死箭头 —— 两个现场：**union 行**要问"当前选中分支"（标量支 / unset 摊开什么都没有），**列表行**要看"数组里到底有几项"（`terms: []` 这种空数组不许挂 ▶）。"必选缺值一律给箭头"那条捷径也会踩同一个坑，交表现器回答。
- **「（未设置）」哨兵永不落盘**：哨兵代表"这个键不存在"，两条通道都要守 —— ① 节点 `SelectedEnumOption` 的 setter 里哨兵一律走"删键"出口（union 走切支、map 条目走 `UnsetEntryValue`、其余可选标量走 `ApplyEmptyValue`）；② 行上"候选项 → `Node.Value`"的同步通道遇到哨兵直接 return。漏一条就会看到左侧是（未设置）、右侧 JSON 里躺着 `"font": "-1"`。
- **内联元组的值是"项节点"画出来的，懒建不许省、判据也不许只看类型**：≤4 项全数值的定长元组走行内编辑器，编辑器内容就是 `node.Items`；项节点被懒建闸门省掉时行上只剩几个空槽。而内联按设计不产子行、也不挂箭头 —— 嵌套层级的 `position_source[block].pos` 就是这样变成"没有编辑器、没有 ⊕、点不动"的死行。判据要看值（文档里那份数组长度与类型项数不一致时不内联，退回元素行）。
- **必填数组容器的空壳不许手写 `[]`**：结构空壳是 `{}`（里面的必填键交给不动点），数组必须按默认值代数给出**下限那么多项** —— `[int] @ 3` 的 `[]` 从第一拍就非法：行上永远挂"列表长度 0 < 下限 3"，内联编辑器也没有可编辑项。
- **⊕ 的判据是"还没有值"，不是"可选"**：可选性只管"能不能删键"。必填容器缺值时既没有编辑器、也不能删键、又常常摊不开子级，⊕ 是它唯一的起值入口；把 `!IsRequired` 写进 ⊕ 的判据，用户面前就是一行永远点不动的死节点。
- **定向重建的值必须从活文档里取，不许拿节点自己的旧快照**：用 `node.Json` 建新节点时，"值刚写进父容器、节点快照还停在上代"的场景会把上一支重建回来（下拉变了、右侧文本也是 `{}`，一拍重建之后行又弹回旧支）。值是"父容器按键身份现取"，取不到才退回快照；**键被删掉时取到的 null 也算活值**。
- **键来自固定候选表的条目行不许给"重命名"入口**：键不是自由名字、而是**类型 / 注册表成员**（components 的 component id、attributes 的 environment_attribute）时，改成任意文本当场就是非法文档；重命名只属于能自由命名的 map 条目。要换这种键只能删条目再从"新键"行的候选下拉里加回来。
- **展开/折叠是行内模板按钮，不是装饰**：三套行模板共用一个展开器；可见性只有一条判据（真的有子级 / 必选容器）；悬停有反馈；箭头角度跟展开态走，不要用 `ToggleButton.IsChecked` 双向绑。
- **展开器换成 `Button` 之后，所有"按 ToggleButton 认展开器"的判据都会静默失效**：Ctrl+点击整棵展开/折叠就是现场 —— 点了没反应、行上还看不出异常。判据一律按**样式**或模板认，不按控件类型认。
- **"条目"不等于"父级的条目集合"**：union 的列表分支把子项上提到 `SelectedUnionChildren`（`Parent` 是 union 行、`Items` 是空的）。定位列表项命令的 owner 必须"谁真的装着它"：从 `item.Parent` 逐级上溯 + 退回建命令时捕获的那个列表节点，集合依次查 `Items` / 列表支的 `SelectedUnionChildren`；命中不到要写 trace，不许静默哑掉。反过来，**"在父级 `Children` 里"不等于"是列表条目"**：map 条目也在 `Children` 里，算错就会给动态键行挂上三颗找不到 owner 的按钮。
- **"这一项是列表条目"还必须能覆盖"只有一个元素"的那一帧**：重建后的条目若不再重挂"删掉这一项"，行上的 ⊖ 会当场消失；漏判的根源同样是"只查 `Items`"。
- **列表项的三个命令（删 / 上移 / 下移）下标必须是"活的"**：把下标捕获进闭包，重建后 ▲▼ 会当场消失（按钮还在、命令是 null），连按两次 ▲ 时还会用旧下标**把别的项挪走**。三个命令一律"执行时现问 `IndexOf(item)`"。
- **列表项按钮有两个独立的失效源**：① 可用性读的是"这一项在集合里的下标"，而 WPF 只在"命令可用性变化"事件时重问 —— 从不发这个事件，增删/移动之后按钮就停在上一代的灰/亮；② 闭包捕获的是**本代**列表节点，重建换掉它之后下标恒为 -1。另外"更多/尾部追加"行也是列表子行，会把列表节点上那几颗 null 命令渲染成空按钮。
- **"当前项"不能靠"第一行"兜底**：行视图的键盘事件在隧道阶段抢在行内编辑器前面，判归属必须按**事件目标**（文本框 / 可输入下拉 / 键名输入框）；没有目标行时不许兜底到第一行（那等于"重命名框里的左右键和回车全作用到第一行"）。
- **一行只能有一个删除出口**："可选字段清空"与"map 条目删除"会同时成立 —— 加出来的 map 条目行上当场出现两把垃圾桶。清空入口要排除 map 条目与列表子行。
- **map 条目行是一个"行实体"，不是文档键的影子**：① 删除入口在行首，行尾那格只留加入/重命名；② 条目的（未设置）**只把右侧 JSON 的键去掉、行留在树上**（走值通道、不抬结构变更 —— 抬了父级就会按 JSON 重建，这一行当场消失）；③ 键已经不在了，删除就退化成"摘掉这一行"。
- **定长结构（tuple / `#[length=N]`）的增删守卫要一致**："加项"这条 API 也必须按**生效的 owner 类型**拒绝静态下标本身不可删的形态；只按节点自身类型判会漏（工厂会把定长 list 归一成 tuple），现场就是"加出来却没有删除按钮"。
- **列表项的删除不许静默无效**：遇到"下标越界"直接 return 会吞掉"文档里的数组已经空了、节点上还留着一项"这种陈旧项，用户看到"删自己的按钮点了没反应"。越界要当成"清掉这一行陈旧项 + 让子级重建"；正常删除后也要强制"子级未建"。
- **列表条目的增删要通知"能重建的那一层"**：union 的列表/结构分支本身不会进父级的子级集合（子级被上提），在它身上抬结构变更等于重建一个临时壳 —— 宿主找不到父行、重投影出来的还是旧树。分支节点也要挂到 union 上，通知要用"父级的三个子级集合里有没有它"逐级上溯。
- **动态键是数据，不许按"新结构没声明"剪掉**：清派生成员用静态字段名建"已声明集合"，而 map 容器一个静态字段都没有 —— 于是 map 里任何一个值变化触发父级重建时，整张表的条目会被当成"上一支的残影"删光。新结构有动态键字段时这些键一律保留。
- **动态键的键类型常常是 `type` 别名**：属性挂在别名目标上，解析必须按符号表穿透 `Reference` 再取属性。
- **动态键在 MetaType 侧是"字段类型 = `Tuple[键类型, 值类型]`"**：泛型形参落在键上时 `field.Key` 为空，模板替换必须先拆这个 Tuple 分别求值，否则键退化成 `Any`、候选与泛型替换一起丢。
- **动态 map 占位行每轮只能加一个键**，否则 walk 永不收敛；给"祖先是缺省可选字段"的 map 加第一条键时，容器要能挂到多层上。
- **`[[key]]` 只能在"持有那份 JSON 的节点"上求值**：泛型实参/映射值里带动态索引时，在父层先求值会把 `[[key]]` 读成 `%none`、整支烤成 `any`。读过运行期数据的实参保留声明、连试求值都不做。判定"实参带动态索引"要看穿引用与字段；但符号表只许在最外层（depth ≤ 1）查 —— 逐层查会让真机的可选 union 退化。
- **`Indexed` 全被过滤掉时不许返回空联合**：空联合会被下游当成"文档里声明为 `()`"，也会让 spread 走进"目标联合没有结构成员"的假象；解不开就退 `any` + 诊断。`indexed` 也不许清类型实参。
- **`SimplifyStruct` 对"已归一的动态键字段"必须原样保留**：再走一遍会把"键是 union"的字段按成员展开，破坏幂等。
- **模板形参引用要按最后一段名匹配**（映射里的引用可能带模块前缀）；`use a::b as Alias` 的别名要由 visitor 带出来；单字母 `B` 不能当类型形参名。
- **visitor 是"new + 逐属性拷"**：新增的属性载体必须加进拷贝清单，否则只活到中间对象上（裸 `#[id]` 就这样丢过一轮）。
- **id 空间不能做跨实例静态缓存**：按 (registry, version) 当键会把不同实例的结果串在一起。
- **求值诊断只写日志＝用户永远看不到**：索引类诊断（不可索引 / 越界 / 超上限 / spread 非 struct / 形参数量不符 / 动态键没命中成员）必须同时挂到行的 `Error` 上（只留前 5 条，其余给计数）。
- **良性跳过绝不许写成行徽标**："节点没有父级且不是文档根"是**预期**情形（重建换了节点、编辑器还握着旧实例），写进 `node.Error` 就成了永远消不掉的黄色感叹号；行徽标只许来自"当前状态"的校验。
- **`any` 行的值控件与写回必须一起跟着选中的 JSON 类型走**：只换值控件不换写回出口，写回仍按"原始 JSON"取值 → 一律返回 null → 落成删键（"选中 String 敲第一个字符，标签从 JSON 里消失、行也没了"）。写回按选中分支取值：String→文本值、Double→数字文本、Boolean→勾选态；List/Struct/原始 JSON 回当前值让写回幂等；只有哨兵回 null。
- **分支的显示名与判据必须分家**：显示名只给下拉看；判据一律走**稳定的键**（字面量的小写稳定形态），否则改个大小写就静默失配 —— 下拉显示 Boolean、值控件停在原地。
- **两个 `any` 不是一回事**：声明就是 `any` 的槽位（新键 / ⊕ / 列表新项）取**首分支**；"求值解不开退化成的 any"必须保持 `{}`（那条兜底写 `false` 会把结构槽变成非法值）。
- **切 any 分支时值"能留就留"，且草稿要排在当前值之后**：一律换新分支默认值会把用户刚敲的值顶掉。顺序：值在新分支成立 → 原样留；当前是真值 → 先标量互转、再走四条搬运；当前只是上一支的默认壳 → 还分支草稿；都没有才用默认值。标量互转只保证"能解析"，会规范化文本形态，别写成"无损"。
- **list 形态的 any 也得有 ⊕**：判据要认"声明 any + 值是数组"，缺一个就是"选了 List 之后一行按钮都没有"。
- **map 条目"清空值"不许走普通可选字段的删键**：数字框清成空会落到清空出口，按普通字段删键就是**删键 + 断子树**（"清一下值，整行没了"）。条目清空只有一个口径：只删键、行留树上、类型下拉停在原分支，最后发一次值通知。
- **占位行的显示名只写节点字段，绝不当键写进 JSON**："自定义数据"这类名字给到 `Desc`/`Key` 才看得懂；键身份、`JsonPath`、导出都不受它影响。
- **换 JSON 类型必须当场作废旧形状的子级**：值换了、子级还是上一代 → 切成 string 之后结构才有的「新键」子行仍挂在下面（一条点不动、也写不出东西的行）。改类型要"清子级 + 抬结构变更"；值通知只刷摘要。
- **可选 `any` 行的"（未设置）"哨兵要在必选性落定之后补**：建树期父级还没写可选性（默认必选），补早了候选表里就没有哨兵、这个键永远清不掉；哨兵本身也必须真有动作（静默删键 → 清镜像 → 最后发一次值通知）。
- **行内提示（水印）不许放到控件格外面**：输入框 `Stretch` + `Auto` 列时列宽被提示语撑开、字压在框里，整行读起来就是一句说明文字；挪到框外面又会被读成"水印溢出了键入范围"。正确形态：输入框自己定宽（与其它行的值编辑器同宽），提示语叠在**同一格的框内**，靠裁剪 + 内侧边距夹住，键名一敲就隐藏。

### 文本 / 锚点通道（两个视图同代）

- **整篇写回只能有一个执行者**："保住外部引用的重排"与"换一代 AST 的重载"在同一拍互相覆盖时，文本会变成"用户文本 + 树回写文本"——解析器报"根结束之后还有内容"，而屏幕上那段文本却完全合法。重入只记"最后一次"；写完必须校验文档真的等于目标文本（不中就重算边界再写一遍）；写回与锚点重建必须在同一次调用里完成。
- **换 AST 的载入不许换"文本状态"实例**：换实例后外部持有者继续写在旧代上，文本与 AST 从此不同代（"改了值 JSON 不动 / 再敲一个字就丢"）。原地重解析，且写回与重解析同一次调用。
- **区间表是锚点的"真相"，就地改文本必须同步挪它**：替换文本只会让编辑器的文本锚点自动平移、**不会**改区间表；手术式写入口若只更新被替换的那一个节点，下一次读锚点就按旧位置现建 → 选区整体偏移（"上一处改完，下一处改的时候残留/啃掉一个字符"）。
- **登记表的键是强引用：换了节点就必须搬登记**：父级那个值换成新对象后，旧对象若还留在表里就被字典一直吊着不放（旧 AST 一起泄漏）；换下来的旧值必须从区间表与锚点表里都移除。
- **整篇写回必须保住光标**：整篇替换会把光标夹到文末，用户逐字符继续敲的字就落到根外面（解析器报"根结束后还有内容"，行号正是根结束那行）。写回前定位"所在的最内层节点 + 相对偏移"，写回后按同一节点的新区间落点；换 AST 的重载才退化成夹紧。
- **整篇替换文本会杀掉语法波浪线的锚点**：下一次绘制会直接抛 `InvalidOperationException`（"删节点必崩"）。整篇写之前先清掉错误波浪线的 overlay，renderer 自己也要判"锚点已删"。
- **文本→树的差量同步必须先"换根"、再重建锚点子树**：反过来的顺序用**旧**值重建，重建出来的子树里没有新键（JSON 里多了键、树上只有"新键"占位行）。顺序固定为"值补丁 → 重指/接新根 → 重建锚点子树"。
- **只重指"节点的值"不够，求值现场也要跟着换**：换根之后节点上的求值现场还指着旧对象，按同层兄弟键求值（动态索引）读到的就是上一代的值 —— 右侧把 `block` 改空、左侧 `properties` 照样解成旧方块。每个节点 + 摊平后的合成根都要重指。
- **右侧文本必须按"视图同代"对账，不能只重排**：重排的是编辑器自己那一代 AST；模型根被整篇替换过时，右侧会停在旧形状上（文档根已是数组、右侧还是对象）。同步前先比较"格式化后的编辑器根"与"格式化后的模型根"，不一致就把模型这一代灌回编辑器再重排。
- **程序写的文本不算用户输入**：手术式落盘之后编辑器会抬文本变更事件；不压住回写通道就会被当成用户输入 → 防抖 → 文本→树同步 → 锚点重建 → 承载光标的行被换掉（"每敲一个字符就丢焦点"）。同时"文本→树"在编辑器有焦点时只验证语法、不落地，失焦后补跑。
- **标量 / 数字编辑只刷诊断，不许重算 Head/Kind 或重建无关父级**：值变化不改变行形状；`RefreshHead` 的空属性通知会让行模板/编辑器重新求值，把正在输入的控件换掉（数字框"敲一个字符就失焦"）。父级只有在"声明里按这个键做 spread / Indices"或"父级读过运行期数据且当前行有候选表"时才算依赖；焦点还在行内编辑框时，真正的依赖重建延后到失焦补跑。
- **数字范围只警告、不夹取**：越界值照常落盘，只给 warn，不能改成 error，也不能把值夹回边界。
- **消化完文本后，回写要取编辑器"当前"文本**：消化过程中树侧可能已经整篇回写，拿进来时的快照会让模型的文本与屏幕上的 JSON 不同代 —— 复制/保存导出的就是上一份。
- **复制/导出前必须先把"被推迟的那一代"补跑完**：文本防抖、延迟重建、局部拼接都可能让右侧已经出现新结构、左侧投影还停在上一代（"点了复制才出现结构，树里没有"）。复制/保存前先补跑推迟任务，并让投影与文档按路径 + 实例身份对账，再取文本。
- **"一有作废就整篇回退"在文本侧同步里没有可达路径**：形状变化的节点总被锚点覆盖，那条逻辑只是安全网，不要当成主路径。

### WPF / XAML

- **`ListCollectionView` 不支持范围操作**：多行 Add/Remove 抛"不支持范围操作"。拼接必须"改数据 + 单次 Reset"，滚动位置另做锚定。
- **`ContentTemplate` 会压掉 `ContentTemplateSelector`**：两者同时给时只有前者生效，选择器看起来"永远不选中"。
- **`Style.BasedOn` / `TargetType` 不能用 `DynamicResource`**：它们是 CLR 属性，一实例化就抛 `XamlParseException`。
- **`VectorTextBox` 自带的 `WaterMarkerText` 在行内看不见**：内容宿主的不透明底盖住水印；行内空值占位要自己叠一层 `TextBlock`。
- **`VectorTextBox` 的底色在构造函数里是"本地值"**：它压过一切 Style setter（包括 `BasedOn` 派生的透明样式）—— 行内想要无底色，只能用"XAML 上显式的本地值"或"把默认值挪进样式"；"按底色刷描边"的逻辑遇到透明主题必须直接跳过。
- **行内文本框拖不出选区 = 外层列表的"拖拽滚动"抢走了鼠标捕获**：滚动视图在按住拖拽超过阈值后会 `CaptureMouse()`，把鼠标从正在选字的 `TextBox` 手里夺走（选区正好停在跨过阈值那一下）。判据不是"内容宿主是什么控件"，而是**按下点落在哪** —— 命中 `TextBoxBase` / 按钮 / 滑块 / 滚动条时，这一次按住不许升级成拖拽滚动。
- **`TextBox.Padding` 会被推给内容宿主，模板里再绑一次就是两倍**：`TextBoxBase` 把 Padding 写到 `PART_ContentHost`，宿主的模板又把它当内容边距用；行内模板若再绑一次 `Margin="{TemplateBinding Padding}"`，字形离左边框就是"边框 + 2 倍内边距 + 控件自带的光标内缩"。
- **行内文本框的字要"整框居中"就得让内容宿主跨过顶部定位线那行**：定位线占 Grid 第一行时，内容宿主只拿到剩下的高度，字在"去掉定位线之后的那块"里居中 —— 看上去还是贴着上沿。宿主跨两行，定位线改画在宿主之上并关掉命中测试。
- **行内控件比行还高，就会被行容器连边框一起裁掉**：行容器模板的根 `Border` 带 `CornerRadius`，超出行的像素会被裁 —— 皮肤的 1px 边框 + 上下两条边带正好落在被裁的那几像素里，现象是"顶部和底部没了"。行内编辑器高度一律不大于行高。
- **`VectorTextBoxStyle` 的模板根 `Border` 绑了 `VerticalAlignment`**：控件一旦写 `VerticalAlignment="Center"`，根 Border 就按内容高度收缩，数字框实际画出来比旁边同高的按钮矮两圈。要拉伸，别写 Center。
- **祖先竖线要"从父行中线接出来"就得让父行自己画半截**：超出行的绘制一律被裁，靠负边距往上伸不行。父行用上下对半的 Grid 只画"行中线 → 行底"那半截，子行那条从自己上沿起画，两截在行边界接上。反过来，`AddTail` / `More` 这种**列表末尾的入口伪行**只画到 `(Depth-1)`：最深那一格在它旁边没有东西可连（悬空的孤儿线），**父级那条一直延伸下来的要留着**；它们的 `Node` 借的是父列表节点（本身"有子级且展开"），子级连线那半截也必须显式排除。
- **展开箭头的 Style 键是 Ctrl+点击整棵子树展开的唯一判据**：行视图按"展开器 Style 实例"认按钮。把箭头换成别的控件时不能直接套共用的 FlatIcon 皮肤（`BasedOn` 它、保留自己的键），否则认不出来、Ctrl+点击静默失效。
- **在这套皮肤里，"一根 1px 灰线 + 半透明文字"会被读成 2D**：旁边控件全是"描边 + 亮带/暗带"的伪 3D，纯平面元素立刻显突兀。要么做成凹槽/描边底板，要么跟着主题底色走。
- **贴图目录要按"实际部署的样子"找，别只信配置**：配置里的贴图目录可能指向一个**根本不存在的目录**，而仓里贴图其实平铺在 `ImageSet\<id>.png`（没有命名空间子目录）。解析要 ① 目录不存在就继续回落；② 同一 id 先试分层 `<ns>\<id>.png`、再试平铺 `<id>.png`。否则图标位永远停在"瓷砖 + 首字母"的占位态，看代码还看不出问题。
- **图标选择器不要把图标单独摆成一格**：图标放进下拉的 `ItemTemplate`，闭合态显示选中项、展开态显示每一行，共用同一份模板；图标源要按 `ItemID` **惰性**查询（只有真正物化出来的行才碰磁盘）。没有贴图的 id 要留定宽图标列，否则同一列里文字会左右跳。
- **图标下拉的"行高"要写在 ItemTemplate 自己身上**：纯文本下拉那版把行高绑到了 combo 的高度，图标这版是自绘模板 —— 不写高度时展开后每行塌到图标那么高。**别**改用 `ItemContainerStyle` 去撑行高：真机上试过会把弹层拖死。
- **名称底板的右沿接不上按钮，是"空组件的 margin"在作怪**：行尾动作列里那组 ▲▼⧉⊖ 在非列表行是**空**的，容器上的 margin 照样占位；再叠上"没有编辑器时那根空列 + 动作组间距"，底板到最近那颗按钮就白出一截。间距要挂在"组内的按钮"上，空组自然归零。
- **`#[id]` 常挂在"求值出来的类型"上，不在声明类型上**：字段的声明类型往往是指令包装（`Mapped` / `Union` / `Reference`），属性落在求值那一层。判"这一格要不要图标位"必须两处都看；只看声明类型，`display.icon.id` 会永远退化成普通下拉（候选却是齐的，特别容易漏）。看得见的 id 空间（`item` / `block` / `entity` / `entity_type`）一律给图标位，缺贴图的项自动只显示文字。
- **附加属性做不了事件触发器**：挂行为用附加属性 + `Loaded` 回调；`CallMethodAction` 指向不存在的方法只静默报绑定错。
- **`TextBlock.Text` 与 `Inlines` 不能同时设**：富文本就得删 `Text`、代码赋 `Inlines`；`FlowDocument` 被复用容器抢挂会抛异常。
- **`Documentation` 带 `///` 前缀、多行还是逗号拼的**：渲染前必须逐行剥 `///`/`//!` 与行首逗号。
- **附加属性 DP 值不变就不会重渲染**：断言里判附加属性比判文本稳。
- **行模板里的裸 `Button` 会吃系统主题 chrome**：仓里没有隐式 Button 样式，`Background="Transparent"` 压不过主题模板（标签变成白色小方块）；只有本地 ControlTemplate（仅 `ContentPresenter`）才彻底。
- **`VisualTreeHelper.GetParent(Run)` 会抛异常**：文档面板里的 `Run` 是 `FrameworkContentElement`、**不是 Visual**，鼠标划过就崩；上溯父级必须用 `ContentOperations.GetParent` 兜底。

### 求值 / 数据

- **ComboBox 转换器会改字面量类型**：往返后字面量从 `int` 变 `string`；unset 判断必须同时认 int / decimal / `"-1"`。
- **转换器必须返回"稳定实例"**：选中项不是集合里同一对象引用就会被清空（"选完弹回"）。转换器按「名字 + 字面量」缓存。
- **颜色取色器的 `HexCode` 是私有 setter**：只能绑 `SelectedColor`，字符串字段配双向转换器。
- **候选下拉的 ItemsSource 一律过"给下拉行做文本+图标"的转换器**：模板绑的是 `item.Text`/`item.Image`，直接喂枚举成员时每一行都是空的；样式里设了 `ItemTemplate` 时 `DisplayMemberPath` 会被它压掉。
- **union 分支的枚举下拉也要有（未设置）**：建支时文档里往往还没有值（分支用 null JSON 建），分支节点若只有枚举候选，镜像到 union 行上的下拉就只能显示"第一个有意义的成员"、点了也退不回去。三处一起守：分支节点建好后插哨兵（分支节点的"必选"没有"可选"含义）、切支写完值按本行的值重新派生选中项、union 行上选哨兵 = 这个键整个不存在。
- **"必选却未选定分支"不许在建子级时挂**：那一刻子节点的"是否必选"还是默认 true（父级建完子节点之后才写），可选字段会被扣一顶假诊断而且永远清不掉。缺必填键由全树建完之后的校验统一报。
- **下拉的（未设置）哨兵必须由父级在"是否必选"落定之后插**：建子级期判"是否可选"恒为真 —— 必选字段会莫名其妙多出一个能删键的项。收口点只有"构造静态字段"与"重建节点"两处，且必须幂等。
- **`Prepare` 里读不到字段的必选性**：必选性是父级建完子节点之后才写的 —— 拿它判断"必填 bool 默认 false"会把可选 bool 也落成 false（且行上假装已选中）。bool 的默认值判定放到物化阶段。
- **清空语义必须走同一条出口**：数字清空 / bool 两个都取消 / 可选字符串清空 = unset（删键），必填 = 挂诊断；否则会出现"行上没了、JSON 还在"或反过来的假象。
- **可选 bool 两个都取消 = unset，不是默认 false**：普通字段删键；union 标量 bool 回到"未设置"并清掉分支镜像。必选 bool 仍保持二选一。
- **成员写入按树序，不按到达顺序**：纯追加会让新键永远排到末尾，和左侧树的相对位置对不上（切枚举、补默认值、⊕ 都受影响）。
- **分页上限与"全部"冲突**：设为最大值的"全部"要绕过页大小截断；"更多"行重投影要落在**列表行**上。
- **懒建之后不能用"子级个数"判有无子级**：要问表现器"有没有能力长出子级"。
- **宽容 JSON 解析器从不抛异常**：坏文本返回部分结果，直接建树会覆盖旧树；所以"语法错误不能污染树"必须在调用处先判。
- **建树期分支不许走值转换**（见前文"分支子树必须建在文档里那份值上"）。
- **建树期不能回写文本**："载入中"这个闸门不仅挡值回写，文本同步也要跳过。
- **文本相等 ≠ AST 新鲜**：编辑器里敲完字，编辑器持有的 AST 还停在上次解析，重建前必须先重解析。
- **改了参与动态索引的值必须重建，但只能延迟一拍**：同步重建会打断动态键输入（占位节点被换掉 → "加了键但 JSON 里没有"）。
- **定向重建按路径找锚点会命中"同路径的兄弟"**：动态键占位行与父容器同路径，路径索引又是子覆盖父 → 拿它重建会造出"没有键身份"的匿名条目行（文件里有、树里没有）。索引要先写优先 + 跳过占位行、锚点本体优先、拒绝没有求值现场的节点。
- **`RefreshNode` 复用建节点那一刻捕获的类型闭包，但别往它里面加"重新求值"分支**：运行期依赖的节点早在结构变更入口就被转成"延后一拍重建"，它根本走不到。`RefreshNode` 必须让路径索引失效，否则 `FindNode` 会把刚被删掉的节点捞回来（"JSON 里键没了、左侧那一行却还在"）。
- **`RebuildNode` 必须把"父级写过的语义"整套带回来**：必选性 / 文档注释 / 键提示 / 条目身份（是否 map 条目、正在编辑的键、动态字段下标、键候选）/ 列表项的三颗命令 / union 显式选择 / 旧节点的展开态 —— 这些全是父级建完子节点之后或运行期才写的，重建只按声明类型重跑一遍会把它们全丢（现象各不相同：可选字段突然变必填、重命名与条目删除按钮当场消失、▲▼ 消失、切走的成员自己弹回去）。两条硬约束：命令必须按**新节点**重挂；条目身份只在"新形态仍然成立"时回填，⊕ 行的折叠态不许继承给"刚长出值"的新节点。
- **摊平根的顶层节点重建必须同时换顶层集合里的那一项**：只换合成根的子级，视图还指着旧实例（子行永不更新），而"按父行重拼"又因为父行是合成根而失败 → 整表重投影。顶层区的行重拼只能按"第几个最外层行"定位。
- **`Diff` 里"对象键集合变了就整体当锚点"对根对象不成立**：根没有行可挂，只能改成"成员增删单独处理 + 公共键继续往下差分"，公共键的相对顺序一旦变了就直接回退。根层的"新增成员"也不许进差分锚点（重建只有声明类型，拿不到建树期的语义）。

### 页面 / 宿主

- **`Console.ReadKey()` 会让被拉起的服务器秒退**：宿主是没有控制台的 WinExe，`ReadKey` 直接抛异常 —— 表现为"进程起来了但管道永远不出现"。
- **无超时的 `ConnectAsync()` 比崩溃更糟**：服务器没起时初始化永远不返回 → 骨架屏不消失、符号表为空、所有 `#[id]` 变文本框，而且一条日志都没有。
- **`Resource` 是 Prism 单例**，VM 走构造注入；初始化没跑过，任何页面都建不出树。
- **树行展开箭头不能复用宿主的 `RightArrow` 资源键**：Generator 的 `Window.Resources` 常把这个键重定义成 ImageBrush；`Path.Data` 一旦拿到 ImageBrush，布局阶段就抛 `InvalidOperationException`，页面只剩工具栏、内容空白，看起来就是启动假死。树行箭头要用私有 Geometry 键或内联 Geometry。
- **生成器页面只声明 EntryId**：所有入口页统一继承基类，页面里不许自带引擎逻辑（同步 / 默认值 / 防抖重建只有一份）。
- **外部生成器复用树视图时，版本、符号 Index、root 必须一起切**：只换页面入口名会出现"树按旧根求解"的半切换状态；默认文档、reload、入口形状校验也必须读同一份当前 root。
- **入口配置文件缺了不许让整条初始化静默跳过**：这个文件不在仓里（安装包才带），旧写法第一句就是"文件存在才继续" —— 缺文件时注册表与符号表双双为空，页面变成 `null`（右侧一个 null、左侧一行、状态栏一条提示都没有）。缺文件按默认路径继续、读坏了记一条 note 一样继续；默认文档出口的契约是"绝不返回 null"，但缺省代数对空联合 / 没解出的指令回的是 JSON null（**不是 C# null，`??` 拦不住**），必须过"能不能物化"再退 `{}`。
- **入口模板本身可能是"另一种资源"，引擎不许拿它建树**：某资源的模板文件是一份函数数组，而根声明是结构 —— 整页退化成 `any` 原始行，看着像求解/渲染坏了，其实是默认数据坏了。载入默认文档要先验根形状（结构要对象、列表/元组/原始数组要数组、any/解不开不判），不符就退回代数默认值并把"根形状与声明不符"摆在状态栏。
- **`any` 行的子行与列表语义要跟着文档形状走**：借的是 struct/list 的表现器（数组项挂在 `Items` 上），但基类只看 `Children`、列表语义只按类型判 —— "数组形态的 any 行"会一个条目都不出行。子级取 `Items`，并给表现器加"节点感知的列表判据"。
- **AvalonEdit 必须用持有 `JsonTextState` 的那个编辑器**：只有它与树共用同一批 JSON 值。
- **编辑器 `Text` 不是依赖属性**：禁止在 XAML 里绑 `Text`（真机 `XamlParseException`）。
- **展平后合成根不在顶层集合里**：按路径重指碰不到它 → 顶层增删写进旧对象；"文档根"标记必须有唯一赋值点（只有"在顶层集合里且没有父级"的节点才是文档根），漏赋值时根标量编辑会走进"替换根"的拒绝分支（值只留在节点上、文档没动）。
