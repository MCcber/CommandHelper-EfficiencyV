# Mcdoc 树渲染管线：业务模型与踩坑备忘

> 只写两件事：「业务怎么理解」（含两个视图必须同时成立的契约）、「哪里容易踩坑」。
> 不写功能清单、不写实现方案、不写进度、不写待办、不写实测数字、不写文件目录 —— 做完的事不进这份文档，只有踩过的坑留下来。

## 一、术语速查

| 词 | 含义 |
|---|---|
| dispatcher | mcdoc 的 `minecraft:resource[<registry>]`：按资源 id 落到具体 schema。本项目拿它当"页面入口" |
| EntryId | 页面传入的 dispatcher id（如 `dimension_type`），生成器页面的唯一参数 |
| spread | `...SomeType`：把另一个结构的字段摊平进来，simplify 阶段落地 |
| `#[id]` | 字段值的取值来源标注（registry / tags / include / exclude / prefix），决定下拉候选 |
| 判别键（必选 Enum） | 决定同层 dispatcher/spread 解成哪一支的必填字段；界面上是下拉，候选来自 `#[id]` 的注册表/调度器空间 |
| 物化 / 不动点 | 把行上已显示、文档里没有的必填值写进 JSON，再整篇重解；重复到某一轮不写任何键（上限 3 轮） |
| union / unset | 联合类型；下拉里的"（未设置）"哨兵表示**删掉这个键** |
| inline tuple | ≤4 且全数值的元组，一行内渲染完，不产子行 |
| Head / Row | Head 是 presenter 产出的"这行怎么画、能点哪些按钮"；Row 是投影出来的扁平行对象 |
| 懒建 | 子级到展开时才建（`EnsureChildren`），默认展开深度 3 |
| NF / 指令 | 归一形态 vs 求值指令（Reference/Concrete/Template/Mapped/Indexed/Dispatcher），见 §二 |
| RebuildAnchor | 最近的容器祖先：运行期依赖变化时"从哪一层重建" |
| 键身份 | 一条 entry 在 JSON 里的位置：`FieldName` + `JsonPath` + `KeyNode`(`RuntimeKey`)。`%key` 类动态索引全靠它 |

## 二、求解模型：混合结构怎么归一

### 2.1 归一形态（NF）

引擎里"能被渲染 / 被索引 / 被合并"的只有：

`Any / Boolean / String / 数值 / Literal / Enum / Struct / Union / List / Tuple / 字节数组`

其余六种是**求值指令**，必须在求值期消掉、不许出现在节点上：

`Reference / Concrete / Template / Mapped / Indexed / Dispatcher`

### 2.2 两个上下文

| 上下文 | 作用 | 生命周期 |
|---|---|---|
| `TypeArgs` | 排队中的类型实参，只被"下一个 Template / 泛型 Dispatcher"消费一次 | `Concrete` 写入 → 被消费后清空 |
| `TypeMapping` | 形参→类型的替换环境；结构体字段以 `Mapped{copy}` 自带环境（唯一惰性边界） | Template/Mapped 写入，可继承 |

规则：**任何指令都不许丢弃它不消费的上下文**。

### 2.3 指令消去规则

| 指令 | 规则 |
|---|---|
| Reference | 命中 `TypeMapping` → 直接替换；否则按"声明模块 + use 别名 + 祖先模块"解析后**带同一上下文**继续 |
| Concrete | 实参先按当前上下文求值 → 写入 `TypeArgs` → 求值 Item（保留 `TypeMapping`）；**实参带动态索引时保留声明、不在此求值**（就地求值会把 `[[key]]` 读成 `%none`），由消费方在自己的节点上求值 |
| Template | `TypeArgs` → `Mapping`（外层为底、内层覆盖；缺省 `any`）→ 清 `TypeArgs` → 求值 body |
| Mapped | 合并 mapping（外层为底、内层覆盖）→ 求值 Item |
| Indexed | **带同一上下文**求值 child（不清 `TypeArgs`）→ 按索引代数作用在 NF 上；无索引时等价恒等 |
| Dispatcher | 解析成员目标；`TypeParams` 非空时用当前实参替换后再求值 |

### 2.4 索引代数（定义域 = 全部 NF）

| 被索引的 NF | 语义 |
|---|---|
| Struct | 按字段名 / 动态键（`Tuple[键,值]`）取类型；未命中走 `%unknown` / fallback |
| Union | 逐成员索引后取**并集**（去重保序，非 struct 成员跳过并报告，上限 64，全失败才 `any`） |
| Tuple | 静态下标取项；动态索引对所有项求值后并集；越界 → `any` |
| List | 取 `Item` |
| Any | `any` |
| 其它 | `any` + 诊断（可见，不静默） |

### 2.5 节点边界与诊断

- 工厂求值后若仍是指令 → **换成 `any` + 保留诊断**（"未解开的类型包装：X"）。渲染层因此只看到 NF：Struct/Union 永远不会是 Text/Raw，`any` 是唯一 Raw 兜底且**必须带诊断**。
- 求值期的诊断（引用解不开 / 未知调度器 / 不可索引 / 联合成员未解出）统一挂到行的 `Error` 上。
- 空联合 `()`（文档里真的声明成空）是合法 NF，单独给"存在性谓词"诊断。

### 2.6 两条容易被忘的语义

- **spread 的 union 语义**：`...U`（U 是 union）合并所有 struct 成员的字段；非 struct 成员报告跳过；一个都没合并时补"未知字段"占位。
- **mapping 合并**：`Template`/`Mapped` 的映射以外层为底、内层覆盖，模板体里引用外层形参不丢键。

### 2.7 一份文档、两个视图：必须同时成立的契约

用户只看得见"左边树、右边文本、和一份文档"，所以这些不是"测试断言"，而是这个编辑器对用户承诺的东西：

| 契约 | 含义（用户视角） |
|---|---|
| 文本单个根 | 右边的文本永远是一份合法 JSON。语法错误期间树冻结、**程序不替你改文本**；但你一旦在左侧动了树，就按下面那条把脏区域对齐成合法文本 |
| 视图同代 | 屏幕上文本 = 模型里的文本，不能一个改了另一个没跟上 |
| AST 同源 | 树的节点与文本共用同一批对象，否则"树上的编辑永远进不了文本" |
| 行 → 文档 | 一行显示的值就是文档里该路径的值；**比"值"不比"对象身份"**（整篇重排会重建对象） |
| 无孤儿行 | 每一行都能挂到一个存在的父行上 |
| 缩进契约 | 子行必须比父行深（缺省/压缩层可以跳，但绝不许同层） |
| 缺省字段不摊开 | 文档里没有的可选字段只有一行 ⊕，不许挂子级 |
| 键 ↔ 行双射 | 文档里每个键都有对应行，且只有一行（不许"文件里有、树里没有"或残骸行）。**例外**：当前版本不存在的键（`IsUnknownField`）只出**一行**，它里面的子键不出行 |
| 无重复键 | 同一个对象里不许出现两个同名键（物化/追加最容易造出来） |
| 导出 = 屏幕 | 复制/保存出来的就是屏幕上那份文本 |
| 换版本不改文档 | 切游戏版本只换 schema 求值口径，不许动用户已经写的键值 |
| 会话干净 | 关窗体再开是干净的一份默认文档（折叠态、未消化输入都不许带过来） |
| 树侧操作 × 右侧语法错误 | 定位"能包含住脏区域的最小完整结构"，用它**左侧模型**里的同一份整段替换 → 严格解析验收 → 整篇写回 → 排版；定位不到可替换的结构就一个字符都不改（不猜 `}`、不补引号） |
| 输入即文本 | 用户粘进右侧的整篇内容必须被当成输入：**看不见的空白（BOM / 不换行空格 / 零宽空格 / 全角空格）先归一成普通空格再解析**，否则"看着合法的 JSON"会被判语法错误、树按契约冻死，用户只会觉得"粘贴没生效" |

## 三、踩坑清单（都真踩过）

- **非法形状必须给"诚实的形状"**：声明/求值是容器却拿到标量（或反过来）时，节点一律降级成 `any` + 错误诊断（`值与类型不符：期望 X，实际 Y`），**绝不按声明类型摊开子级**。否则树会长出"父是字符串、子却在展开"的幽灵行，"每个键恰好一行"当场就不成立。子级继承也要钉死：父 JSON 不是 Object 时 `fieldJson` 必须是 null。**容器之间也会错配**（声明 struct、文档是数组）—— 根上一份函数数组配上 struct 声明时，四个声明字段照样成行，用户看到的是"树上一堆字段、右侧一份数组，干啥都对不上"，所以"结构要对象、列表/元组/原始数组要数组"要一起判。
- **行与文档比"值"，不比"对象身份"**：一次整篇重排会重建对象，引用相等不是用户看得见的契约；"行的值 = 文档里该路径的值"用内容比较（缓存残骸"行有值、文档没有"照样会红）。真正的身份契约只在"树节点与编辑器共用同一批 AST"那条上守。
- **跨资源存在性只给 warn**：字段带 `#[id=<registry>]` 且值不在注册表里 → 行上挂 warn（不 error、不改值、不弹选择）。拿不到注册表数据时**不判**（离线/版本没有该注册表），但要在 trace 里说清楚，别把"没验过"当成"验过了"。判定要走实例级缓存，id 空间不许跨实例/跨版本串。
- **归一化（空白类字符）必须挂在那条"真正被粘贴走到"的出口上**：粘贴走的是编辑器文本变更 → 防抖 → `SyncTextToTree`；只挂在"树→文本"或"换版本载入"那两条上等于没挂 —— 现象照旧，而且 trace 里连一条归一化记录都不会有（判断"改了没生效"的第一手证据就是日志有没有走到）。
- **物化（把行上显示的值落盘）必须跑到「不动点」，而且每条重建路径都要跑**：物化写一个键就会重建文档，重建又让派发器/动态索引解出新的必填字段（`type_specific.type` → `...entity_sub_predicate[[type]]` → `BoatPredicate.variant`）。只跑一轮的结果是「行上显示 Oak、文档里没有 variant」，依赖它的下游索引永远停在未求解。
- **必填容器没建出来，里面的必填字段永远物化不到**：物化只走「已经建出来的子节点」，而结构表现器在 `json == null` 时直接返回 —— 「必填结构 → 必选枚举」这种两层必填链，里层连节点都没有，校验就一直报「缺少必填键」。物化的第一步要先把**必填容器的空壳**补上（空对象 / 空数组），再靠不动点循环把下一层带出来。
- **判别键的三种"没有值"是同一个意思**：缺键 / `null` / 空串，`...dispatch[[type]]` 三种都会读成 `%none`，同层 spread 一个成员都解不出（行上只剩判别键那一行）。收口不是刷新子行：**父级按新 JSON 整篇重解**、物化到不动点；父级自己的 `Indices` 是空的，索引挂在 spread 字段上，只刷子行永远没用。
- **判别键必须在"第一次求值之前"按声明写进 JSON**：等求值完再写就晚了（`[[type]]` 已判成 `%none`，闭合候选一起丢）。所以工厂要先按**声明**找到「必填 + 有闭合候选」的字段写进 JSON（判别键常被 Union/Mapped/Concrete/Template 包着，按已求值结构找会漏），求值结果仍是 Struct 时再补写一次并重求值。候选必须走 `#[id]` 的 id 空间出口：拿一次性演示节点去问渲染层的方法，在 union 标量支上会静默拿不到候选。
- **判别键预写要把空串当成"没有值"**：默认值代数对必填字符串给的是 `""`，把它当成"有值"就会静默跳过预写，`[[type]]` 读成 `%none`。物化那条出口早就把空串算作没有值，两条口径必须一致。
- **"行上显示了默认值"不等于"JSON 里有这个值"**：必填 + 白名单闭合下拉会自动选中第一个候选但建树期不落盘；依赖它的动态 spread 会解析成 `%none`（`advancement.criteria.<name>.trigger` 的子级整片空）。只对**必填**字段物化默认选中值再重建；重建/切支新长出来的子树还没有行，"显示中的候选"要按候选表首项落盘，不能因为「没有选中项」就跳过。
- **候选下拉行的空文本绝不许落成 `""`**：`block: ""` 进了文档 → `#[id]` 行立刻挂"值不在候选内"，靠它做动态索引的 `properties` 整片解不出来。三条一起守：① 文本编辑只在**没有候选**时才允许空串；② 空值时优先落"行上显示的候选"（真 unset 走哨兵分支，不靠清空编辑器）；③ 物化把"键在、值是空串"也算没有值（可选字段只在键已存在时补，绝不凭空插键）。
- **物化写成员不能用纯追加**：父对象里常有同名的空值（`trigger: ""`），追加后成两个同名键，dispatcher 读第一个 → spread 依旧空，行上却"已选中候选"。新建祖先容器键也要按声明序插入，纯追加会把 `parent` 落到别的键后面。
- **物化的容器不许"往上找最近有 JSON 的祖先"**：那是把子键提到根上的唯一通道（删 `display` 却出现 `{ "title": "x" }`）。只有 union 摊平出来的分支层可以借容器。
- **依赖键换掉之后，靠它求值的子树必须"重新求值"而不是"刷新"**：`dispatcher`/`indexed`（`mcdoc:block_states[[block]]`）在兄弟键还没有值的时候只能解成兜底 `any`，刷新只是重跑表现器、用的还是建节点那一刻算出的兜底类型 —— 「第一次是哑的、折叠再展开才好」。正解：值变更后按**声明**找出用这个键做动态索引的兄弟走重建；兄弟之外还有**父级**（`...dispatch[[key]]` 的 spread 挂在父结构上，父级自己的 `Indices` 是空的），顺序先兄弟、**最后父级**（父级重建会把被改的节点一起换掉）。
- **判别键的宿主会被 union 摊平**：Object 支的字段行直接挂在 union 行下（`Parent` 是 union、连文档根都可能是它）。这时按 `DeclaredType` 找 spread 是找不到的（union 上没有 `Fields`），而且根 union 没有父级 —— 判据必须按**生效结构**（union 当前选中的结构成员）去判"这一层是否按该键做动态索引"，并允许 union 自己作为重建目标。
- **"靠这个键解出来的兄弟"要重建，诊断也要按节点重算**：值补丁只改 `node.Json`，整树校验不会跑 —— 「JSON 里改回合法值，行上的感叹号去不掉」。值只影响它自己，所以补丁后按节点重算一次校验，并把它在文档级清单里的旧条目换掉（状态栏计数才不停在上一次）。
- **依赖键把某层的类型换掉时，那一层的值要跟着整形**：`argument` 的类型由 `float` 变成结构，文档里却还留着 `6` —— 行上只能挂"值与类型不符"。整形要 ① 用**声明重新求值**出来的类型做判据（节点上的 `Type` 在值与类型不符时已降级成 `any`，拿它判"值仍然成立"恒真）；② 放在**所有重建之后**（父级重建会把刚重建好的兄弟再换掉）；③ 自己搬 `X→{k:X}`（通用搬运规则不跨数值 kind，`6` 会被丢成默认 `0`），搬完再重建这一支。
- **派生容器"解不出任何成员"时必须退回"没有值"**：`Properties`（`mcdoc:block_states[[block]]`）的 ⊕ 判据是 `Json == null`；切成无属性方块后如果只把子键剪掉、把 `{}` 留在文档里，行上既没有子行、⊕ 又灰着 —— 展开了再切过去就"点不动"。两条一起守：① 剪键时**当场把对应子节点从三个子级集合里摘掉**（只置"子级未建"的标记靠不住，任一拍提前建子级就会把旧 `Json` 带回来）；② 父级重建后再按**声明**扫一遍它的字段：可选 + 声明是调度器/索引 + 按当前上下文求值后零字段 + 值确实是空对象 → 删键。**这条判据不能走"已建好的子级"**：重建出来的父级这一拍子级还没建，按子级遍历会整片漏掉。
- **切支只把值换成新支的形状，分支还要"按新对象再解一拍"**：切支会把 union 的 `Json` 换成**新对象**，而这一支的分支节点是按**旧对象**建的 —— 于是 List 支切 Object 支之后，同层 spread 读到的还是上一支的 JSON（只剩判别键一行、兄弟字段一个都不出现），手动再触发一次重建才会好。切支收尾要按**当前文档**连做两次定向重建（第一拍把分支建出来、第二拍让它绑定新对象后再解），而不是只排一条延后重建。
- **切分支必须发一条值通知，而且只能发一条**：剪旧键 / 补新支默认结构 / 值转换都会改文档，但"形状没变"时转换会早退，于是整段切换一个字节都没告诉宿主 —— 右侧 JSON 停在 `{}`、行停在上一支。收口在两个入口（下拉 setter 发一次；程序化切换压住它、按"值快照变没变"在收尾发一次），重复发会让重建排两遍。
- **切分支要丢掉「旧成员声明、新成员不声明」的键**：结构分支的字段行是上提到 union 节点上的，而那些键留在文档里 → 切完 `terms` 还和 `block` 并排出现在行上。剪枝要在把值转成新分支之前，按「求值成员的字段集合」做差集，且只对「旧新都是结构」生效（标量/列表/any 成员一个静态字段都没有，剪下去会把要搬运的旧值先吃光）。
- **切成员 = 清旧成员的键，但"值仍成立"的用户数据要留**：① 新成员不声明的键一律删（切走后 `terms` 残影）；② 两边都声明的键，值在新声明下不成立才删（旧成员 `x: int` 带到新成员 `x: string` 上、方块 A 的 `facing` 落到方块 B 上）。判定出口就是"值是否仍成立"（枚举命中候选 / 字面量相等 / 同种类）；两边都声明且值合法就**保留**，那不是残影而是用户的数据。"保留旧键"只属于**换游戏版本**那条路径。
- **剪键只有一条规则，但有两个入口**：union 走"重置选中分支"，依赖键（方块 / 枚举成员）走"清派生成员"；两个入口都要在"切换这一件事"上调用（只在下拉切换里调、程序化 setter 不调，就会留下旧成员的键）。
- **分支子树必须建在文档里那份值上**：建树期走"值转换"等于把分支子树建在"新成员的默认值"上 —— 文档里那份 JSON 一个字段都没传下去，所有靠同级键的动态索引在分支内部全部取不到键。值转换只在用户真的换分支时用。
- **值转换的四条搬运规则靠"旧类型 = 切走的那个成员"，不是 union 声明**：`X→[X]`、`[X]→X`、`X→{k:X}`、`{k:X}→X` 都要求"旧成员类型 ~ 新成员类型"；把 union 声明当旧类型传进去，这四条永远不会成立（任何成员都跟 union 不同型）—— `{"v":"a"}` 切到 `string` 支会落成 `""`、`"a"` 切到 `[string]` 支会落成 `[]`。
- **"形状相同就不动"要配一条"值落不进这一支"**：只按"是不是对象/数组"判，`[int]` 切到 `[string]` 支会把 `[1,2,3]` 原样留下（行上一条条"值与类型不符"）。判据要连条目类型、tuple 项数、`#[length]` 区间一起判：落得进就一个字不改（用户数据优先），落不进才把转换结果落盘。
- **union 标量支的"空值"不是 unset**：切到 `string` 支时转换写出来的是 `""`，回写出口若按"可选字符串清空 = 删键"处理，就把**分支身份**一起删了 —— 文档里没有这个键，下一次重建只能回到未设置，用户看到的是"选了 String 分支立刻弹回（未设置）"。unset 只走下拉里的（未设置），绝不靠"清空编辑器"。
- **union 选「未设置」不等于只删键**：删键之外还得清**分支镜像**（标量编辑器种类 / 候选表 / 选中项 / 列表支镜像 / 是否闭合下拉）、清分支子级、折叠，并且**返回"真的变了"**让行重投影。少任何一步，行上就留一个写着旧值、点不动的死编辑器。
- **条目的（未设置）必须"先清镜像、再发值通知"**：只删键时分支镜像还挂着，宿主收到值通知会按"这不是结构分支"把节点旧值重新写回文档，键当场又回来。顺序钉死：静默删键 → 清镜像 → **最后**发一次值通知。
- **同值能匹配多个 union 成员时，按"具体程度"选支**：`"black"` 同时命中"枚举支"和"字符串支"时，多命中就放弃会让**每次重建都把枚举支打回字符串**。具体度：字面量 > 枚举 > 普通同型 > `any`，并列最高仍不猜。
- **union 选默认分支时 `any` 成员不许压掉结构支**：`any` 匹配一切但具体度最低；"精确匹配"阶段它会胜出（结构支因缺必填键判不匹配），于是"对象被当 int 渲染 / 切过去就弹回 Int"。兜底要按 JSON 形状重挑，且**只作用于显示层**；一旦放宽求值会把 union 塌成单支，行再也切不了分支。
- **union 行的分支列表不许是 null**：空联合 `()` 是合法 NF，给 null 会让行上的"取第一个分支"直接抛。
- **解不出来的 union 成员不许粘在选择上**：声明不是 `any`、求值却退成 `any` 的分支（例如 NBT 分支要靠同级 `type` 才能解）切过去要**立刻回 unset + 挂诊断**；否则行上留一个"看着有编辑器、其实写不出合法值"的死分支。判据用**声明形态 vs 求值形态**，不许按名字特判。
- **`#[id]` 候选必须过版本过滤**：调度器成员带 `#[until=1.21.5]` 这类标注时，成员表仍然会把它列出来；候选不过滤就会让用户选到"求解期会被滤掉"的键 —— spread 解不出、只剩一条"没有结构成员"的诊断，且切走再切回也不会自愈（值一直在文档里）。判别键物化取候选时同样要过版本门控：同一字段常被写成"版本变体 union"，不问版本就会把另一支的候选写进文档（`infiniburn` 写进方块 id 那类现场）。派生规则：`#[id(..., tags="required")]` 的候选只能是 tag，不能混进注册表成员。
- **当前版本不存在的键只出一行、不解析子树**：走专门的"遗留键"表现器（不建子级、不给编辑器），行首只放标准图标按钮 + 行尾黄色 `!`；文档里那份值**原样留着**（换版本照"换版本不改文档"执行）。切到声明这个键的版本时，同一份 JSON 整树重建就把子树就地建出来 —— 数据从没丢过。三条硬约束：① 未声明键必须在建节点时就打上标记且 `IsRequired = false`（删除原语自己守"必填不许删"，否则一个都删不掉）；② 标记必须在建节点**之前/当下**打上，事后再打已经晚了；③ 行尾不再挂诊断徽标与删除按钮。行首删除入口分两条路：键还在文档里 → 删键；键已经不在了（右侧把整行删掉之后的残影行）→ 只把这一行摘掉再重拼父行，**不能**走父级重建（同一父级下其它幽灵行会被一起清走）。
- **幽灵行（键已经不在文档里、行还挂着值）必须有删除入口**：切 union 剪键 / 右侧删键之后投影没跟上的那一行，常规四个出口**全都不成立**（节点 `Json` 还在、文档里没这个键）—— 用户看到的就是"左右两侧都不存在的节点怎么都删不掉"。判据是"父级对象里没有这个键"，并入遗留键的删除可见性；命令本来就该分两条路（键还在→删键；键没了→只摘这一行）。
- **"键被删掉"必须折叠，投影侧也要兜底**：可选字段的 `Json` 变成 null（右侧把整段结构删了）时，节点若还留着"展开"状态，投影就会把**早就建好的子级**重新摊到行下面。两处都要守：值变 null 且非必选时立刻折叠；投影对"可选 + 没有 JSON"的节点直接不拼子级。
- **值是 null 之后，子级要放开**：删字段会把"子级已建"冻结，再 ⊕ 时 `{}` 回来了但子行回不来（"结构有了、行没回来"）。删字段还要连 `node.Json` 一起断 —— 只清子级不清值，残留值会被后续物化/回写当成"还在文档里"。
- **折叠态是静态表，必须按"页面实例"分会话**：只按 EntryId 分会话时，关窗体再开（新 VM、新编辑器）会把上一个窗口的展开态带进来 —— 于是"文档里根本没有的字段"被撑开、子行凭空出现，父行还是个 ⊕，看着像"子结构摊到了同层"。会话键 = (EntryId, 页面实例)；`json == null` 的字段一律只留一行 ⊕（记住的展开态不许撑开它）。
- **"添加之后要展开"必须只有一条规则，且新节点按路径预约展开态**：新条目/新列表项在那一刻还没有节点（要等父级重建），所以必须先按**路径**记下"展开"，再抬结构变更，重建出来的节点才是展开的。**列表自己**的展开态也要在结构变更**之前**预约：那一刻手里是旧实例，结构变更会把列表重建一代，新实例按"默认折叠"建出来 → 新项行永远不出现。
- **"加一项"不许有第二条路**：列表行的 ⊕、"在顶部新增"、尾部"追加"行若各写一遍默认值与守卫，只有其中一条会做"揭示新项 + 预约展开态"，于是"点 ⊕，右侧 JSON 多了一条、左侧树一动不动"（用户只能点一下复制把它撞出来）。收口成同一个出口。
- **记住的展开态不许再按"有没有子级"拦**：建节点这一拍"有没有子级"可能是 false（数组刚写进去、子级还没建），拦下来就是"记住要展开、节点却是折叠的"。投影本来就会按需建子级，只留"文档里有没有值"这一条守卫。
- **懒建节点展开必须先 `EnsureChildren`**：展开走的是"只拼这一行子树"的捷径，不经过初次投影那条路；漏了这一步，深度 ≥ 3 的节点点箭头只会得到 0 行（「展开没反应」）。同时要给出「刚建出子级」的钩子（补物化 → 延后一拍重建）。
- **缺省成员不许在"饿建期"把子结构建出来**：关掉懒建（为了"行数 == 节点数"）时，"有父级 && 没有 JSON"这类守卫恒为 false —— 父级只在子级建完之后才赋值 `Parent`。于是缺省的可选成员照样把整棵子树建出来，而投影对这类节点一列子行都不画（只留一行 ⊕）→ "节点建出来却不可见"。修法是让**父级**在创建子级时说清"这是缺省成员"，工厂据此跳过饿建（必填成员不 defer：非法文档仍要摊开子行 + 挂诊断）。
- **"必选 + 缺值"的容器行是死行，除非三件事都做到**：① 空壳要补出来，且判据必须**看穿声明包装**（声明常被 `Mapped` 这类指令包着，按声明 kind 直接判会一路漏写，行上没有编辑器、没有 ⊕）；② 必选缺值也要摊开子级（"没有 JSON 就早退"只对**可选**成立 —— 可选是只留一行 ⊕，必选是非法文档、要摊开子行并各自挂"缺少必填键"）；③ 展开箭头要真的能点出东西（"必选且无值"一律给箭头，展开是这一行唯一的入口）。三条缺一条，用户面前就是"Argument 展开失败"。
- **展开箭头的判据用「真的建出了子级」**：按类型猜能让有子级的行没箭头、空 union 挂死箭头；已建就数子级个数，没建才按能力预测。可选且文档里没这个键的仍然只给一行 ⊕。
- **展开/折叠是行内模板按钮，不是装饰**：三套行模板共用一个展开器（`Button` + 切换命令），可见性只有一条判据（真的有子级 / 必选容器）；悬停有反馈，箭头角度跟展开态走，不要用 `ToggleButton.IsChecked` 双向绑。
- **"条目"不等于"父级的条目集合"**：union 的列表分支把子项上提到 `SelectedUnionChildren`（`Parent` 是 union 行、`Items` 是空的）。定位列表项命令的 owner 必须"谁真的装着它"：从 `item.Parent` 逐级上溯 + 退回建命令时捕获的那个列表节点，集合依次查 `Items` / 列表支的 `SelectedUnionChildren`；命中不到要写 trace，不许静默哑掉。反过来，**"在父级 `Children` 里"不等于"是列表条目"**：`Children` 里也有 map 条目，把它算成列表条目就会给动态键行挂上 ▲▼/⊖ 三颗找不到 owner 的命令（行上多出没法用的按钮）。
- **"这一项是列表条目"还必须能覆盖"只有一个元素"的那一帧**：重建后的条目若不再重挂"删掉这一项"，行上的 ⊖ 会当场消失；漏判的根源同样是"只查 `Items`"。
- **列表项的三个命令（删 / 上移 / 下移）下标必须是"活的"**：把下标捕获进闭包，重建后就 ① ▲▼ 当场消失（按钮还在、命令是 null）；② 连按两次 ▲ 时第二次仍在用旧下标，**把别的项挪走**。三个命令一律"执行时现问 `IndexOf(item)`"，列表表现器建项与重建项走同一个出口。
- **列表项按钮有两个独立的失效源，别只修一个**：① 可用性读的是"这一项在集合里的下标"，而 WPF 只在"命令可用性变化"事件时重问 —— 从不发这个事件，增删/移动之后按钮就停在上一代的灰/亮；② 闭包捕获的是**本代**列表节点，重建换掉它之后下标恒为 -1（"点了没反应"），执行时必须现问 owner。另外"更多/尾部追加"行也是列表子行，它们会把列表节点上那几颗 null 命令渲染成空按钮 —— 列表项按钮的可见性要按行形态收紧。
- **"当前项"不能靠"第一行"兜底**：行视图的键盘事件在隧道阶段抢在行内编辑器前面，判归属必须按"事件目标"（文本框 / 可输入下拉 / 键名输入框）；没有目标行时**不许兜底到第一行**（行上的按钮不选中行，选中下标是 -1，兜底就等于"重命名框里的左右键和回车全作用到第一行"，把它展开后子结构紧跟在它后面，看着像"子结构摊到了同层"）。
- **一行只能有一个删除出口**："可选字段清空"与"map 条目删除"会同时成立 —— 加出来的 map 条目行上当场出现两把垃圾桶。判据：清空入口排除 map 条目与列表子行；"可删的行恰好一个出口、必选字段一个都不许有"。
- **map 条目行是一个"行实体"，不是文档键的影子**：① 删除入口在行首，行尾那格只留加入/重命名；② 条目的（未设置）**只把右侧 JSON 的键去掉、行留在树上**（只走值通道、不抬结构变更 —— 抬了父级就会按 JSON 重建，这一行当场消失）；③ 键已经不在了，删除就退化成"摘掉这一行"。
- **定长结构（tuple / `#[length=N]`）的增删守卫要一致**："加项"这条 API 也必须按**生效的 owner 类型**拒绝静态下标本身不可删的形态；只按节点自身类型判会漏（工厂会把定长 list 归一成 tuple）。现场就是"加出来却没有删除按钮"：按钮与 API 用了两套判据。
- **列表项的删除不许静默无效**：遇到"下标越界"直接 return 会吞掉"文档里的数组已经空了、节点上还留着一项"这种陈旧项（某次结构通知被吞掉留下的），用户看到的就是"删自己的按钮点了没反应"。越界要当成"清掉这一行陈旧项 + 让子级重建"；正常删除后也要强制"子级未建"，通知被吞时下一拍投影自己就能纠正。
- **列表条目的增删要通知"能重建的那一层"**：union 的列表/结构分支本身不会进父级的子级集合（子级被上提），在它身上抬结构变更等于重建一个临时壳 —— 宿主找不到父行、重投影出来的还是旧树（"右侧 JSON 少了、左侧树一动不动"）。两条一起守：① 分支节点也要挂到 union 上（否则连向上找的路都没有）；② 通知要用"父级的三个子级集合里有没有它"逐级上溯，通知到真正挂在树上的那一层。
- **动态键是数据，不许按"新结构没声明"剪掉**：清派生成员用静态字段名建"已声明集合"，而 map 容器一个静态字段都没有 —— 于是 map 里任何一个值变化触发父级重建时，整张表的条目会被当成"上一支的残影"删光。判据：新结构有动态键字段时这些键一律保留。
- **动态键的键类型常常是 `type` 别名**：属性挂在别名目标上，解析必须按符号表穿透 `Reference` 再取属性。
- **动态键在 MetaType 侧是"字段类型 = `Tuple[键类型, 值类型]`"**：泛型形参落在键上时 `field.Key` 为空，模板替换必须先拆这个 Tuple 分别求值，否则键退化成 `Any`、候选与泛型替换一起丢。
- **动态 map 占位行每轮只能加一个键**，否则 walk 永不收敛；给"祖先是缺省可选字段"的 map 加第一条键时，容器要能挂到多层上（只挂一层父容器会无处挂载）。
- **`[[key]]` 只能在"持有那份 JSON 的节点"上求值**：泛型实参/映射值里带动态索引时，在父层（列表容器、外层结构）先求值会把 `[[key]]` 读成 `%none`、整支烤成 `any`（`distribution[0].data` 只解出 `type`，那一行退成原始 JSON）。读过运行期数据的实参**保留声明、连试求值都不做**，交给消费方自己的节点。判定"实参带动态索引"要看穿引用与字段（索引常写在被引用类型定义体里或挂字段类型上）；但符号表只许在最外层（depth ≤ 1）查 —— 逐层查会让真机的可选 union 退化（`player` 变 `player.player` 同名空壳）。
- **`Indexed` 全被过滤掉时不许返回空联合**：空联合会被下游当成"文档里声明为 `()`"，也会让 spread 走进"目标联合没有结构成员"的假象；解不开就退 `any` + 诊断。`indexed` 也不许清类型实参（`Concrete{Item=Indexed(Dispatcher)}` 是"泛型 dispatcher"的唯一写法）。
- **`SimplifyStruct` 对"已归一的动态键字段"必须原样保留**：再走一遍会把"键是 union"的字段按成员展开，破坏幂等。
- **模板形参引用要按最后一段名匹配**（映射里的引用可能带模块前缀）；`use a::b as Alias` 的别名要由 visitor 带出来（别名是 `use` 语句的独立子节点，只取路径会丢掉 `as Alias`）。单字母 `B` 不能当类型形参名（`type X<A, B>` 只会解析出一个形参）。
- **visitor 是"new + 逐属性拷"**：新增的属性载体**必须加进拷贝清单**，否则只活到中间对象上（裸 `#[id]` 就这样丢过一轮）。
- **id 空间不能做跨实例静态缓存**：按 (registry, version) 当键会把不同实例的结果串在一起。
- **求值诊断只写日志＝用户永远看不到**：索引类诊断（不可索引 / 越界 / 超上限 / spread 非 struct / 形参数量不符 / 动态键没命中成员）必须同时挂到行的 `Error` 上（只留前 5 条，其余给计数）。
- **良性跳过绝不许写成行徽标**："节点没有父级且不是文档根"是**预期**情形（重建换了节点、编辑器还握着旧实例），写进 `node.Error` 就会变成永远消不掉的黄色感叹号；行徽标只许来自"当前状态"的校验。
- **跨资源存在性只给 warn、候选外的值不猜**：只挂 warn 诊断，JSON 与选中项都不动。为了"让它显示出来"回写选择，会把用户刚选的选择弹回去。
- **"空的派生容器"还有一个坑：状态标志不算数**：只把"子级未建"标记置回 false 是不够的 —— 任一拍提前建子级，那个"文档里已经没有的键"就带着旧值回来（行上看着有、文档里没有）。删键与摘节点必须在同一处发生。

### 文本 / 锚点通道（两个视图同代）

- **整篇写回只能有一个执行者**："保住外部引用的重排"与"换一代 AST 的重载"在同一拍互相覆盖时，文本会变成"用户文本 + 树回写文本"——解析器报"根结束之后还有内容"，而屏幕上那段文本却完全合法。规则：重入只记"最后一次"（排队中的重载不许被"用即将作废的 AST 算出的重排快照"顶掉）；写完必须校验文档真的等于目标文本（不中就重算边界再写一遍）；写回与锚点重建必须在同一次调用里完成。
- **换 AST 的载入不许换"文本状态"实例**：换实例后外部持有者（树、上一次调用的栈帧）继续写在旧代上，文本与 AST 从此不同代 —— 表现是"改了值 JSON 不动 / 再敲一个字就丢"。原地重解析，且写回与重解析同一次调用。
- **区间表是锚点的"真相"，就地改文本必须同步挪它**：替换文本只会让编辑器的文本锚点自动平移、**不会**改区间表；两处手术式写入口若只更新被替换的那个节点，下一次读锚点就按旧位置现建 → 选区整体偏移，现象是"上一处改完，下一处改的时候残留/啃掉一个字符"。
- **登记表的键是强引用：换了节点就必须搬登记**：把父级的那个值换成新对象后，旧对象若还留在表里就被字典一直吊着不放（旧 AST 一起泄漏）；换下来的旧值必须从区间表与锚点表里都移除。
- **整篇写回必须保住光标**：整篇替换会把光标夹到文末，用户**逐字符**继续敲的字就落到根外面（解析器报"根结束后还有内容"，行号正是根结束那行）—— 看起来像"写了新键但左侧模板崩了"，其实左侧渲染的是上一代树（文本非法期间树按设计不动）。写回前要定位"所在的最内层节点 + 相对偏移"，写回后按同一节点的新区间落点；换 AST 的重载才退化成夹紧。
- **整篇替换文本会杀掉语法波浪线的锚点**：下一次绘制会直接抛 `InvalidOperationException`（"删节点必崩"就是这么来的）。整篇写之前先清掉错误波浪线的 overlay，renderer 自己也要判"锚点已删"。
- **文本→树的差量同步必须先"换根"、再重建锚点子树**：反过来的顺序用**旧**值重建，重建出来的子树里没有新键（JSON 里多了键、树上只有"新键"占位行，条目行不存在）。顺序固定为"值补丁 → 重指/接新根 → 重建锚点子树"。
- **只重指"节点的值"不够，求值现场也要跟着换**：换根之后节点上的求值现场还指着旧对象，按**同层兄弟键**求值（动态索引）读到的就是上一代的值 —— 右侧把 `block` 改空、左侧 `properties` 照样解成旧方块。每个节点 + 摊平后的合成根都要重指（合成根不在顶层集合里，常规重指走不到它）。
- **右侧文本必须按"视图同代"对账，不能只重排**：重排的是**编辑器自己那一代** AST；模型根被整篇替换过（根 union 切支、根标量编辑）时，右侧会停在旧形状上（文档根已是数组、右侧还是对象）。同步前先比较"格式化后的编辑器根"与"格式化后的模型根"，不一致就把模型这一代灌回编辑器再重排。
- **程序写的文本不算用户输入**：手术式落盘之后编辑器会抬文本变更事件；不压住回写通道就会被当成用户输入 → 防抖 → 文本→树同步 → 锚点重建 → 承载光标的行被换掉（"每敲一个字符就丢焦点"）。同时"文本→树"在编辑器有焦点时只验证语法、不落地，失焦后补跑。
- **消化完文本后，回写要取编辑器"当前"文本**：消化过程中树侧可能已经整篇回写（物化必填键 / 重建后重排），拿进来时的快照会让模型的文本与屏幕上的 JSON 不同代 —— 复制/保存导出的就是上一份。
- **"一有作废就整篇回退"在文本侧同步里没有可达路径**：形状变化的节点总被锚点覆盖，那条逻辑只是安全网，不要当成主路径。

### WPF / XAML

- **`ListCollectionView` 不支持范围操作**：多行 Add/Remove 抛"不支持范围操作"。拼接必须"改数据 + 单次 Reset"，滚动位置另做锚定。
- **`ContentTemplate` 会压掉 `ContentTemplateSelector`**：同时设 `ContentTemplate` 后选择器不再被调用（所有编辑器突然消失）。
- **`Path.Data` / 图标按钮的 `Icon` 只吃 `Geometry`**：图标字典里多是 `DrawingImage`，部分条目还引用 png，离开宿主程序会抛"找不到资源"。
- **同程序集 xmlns 不要写 `assembly=CBHK`**：只写 `clr-namespace:...`。
- **`StaticResource` 找不到就抛，`DynamicResource` 静默降级**：跨词典引用统一 Dynamic。
- **`Style.BasedOn` / `TargetType` 不能用 `DynamicResource`**：它们是 CLR 属性，一实例化就抛 `XamlParseException`（图标下拉就这么坏过）。
- **`VectorTextBox` 自带的 `WaterMarkerText` 在行内看不见**：内容宿主的不透明底盖住水印；行内空值占位要自己叠一层 `TextBlock`。
- **`VectorTextBox` 的底色在构造函数里是"本地值"**：它压过一切 Style setter（包括 `BasedOn` 派生的透明样式）—— 行内想要无底色，只能用"XAML 上显式的本地值"或"把默认值挪进样式"；"按底色刷描边"的逻辑遇到透明主题必须直接跳过，否则会把底色再刷回去。
- **附加属性做不了事件触发器**：挂行为用附加属性 + `Loaded` 回调；`CallMethodAction` 指向不存在的方法只静默报绑定错。
- **`TextBlock.Text` 与 `Inlines` 不能同时设**：富文本就得删 `Text`、代码赋 `Inlines`；`FlowDocument` 被复用容器抢挂会抛异常。
- **`Documentation` 带 `///` 前缀、多行还是逗号拼的**：渲染前必须逐行剥 `///`/`//!` 与行首逗号。
- **附加属性 DP 值不变就不会重渲染**：断言里判附加属性比判文本稳。
- **行模板里的裸 `Button` 会吃系统主题 chrome**：仓里没有隐式 Button 样式，`Background="Transparent"` 压不过主题模板（标签变成白色小方块）；只有本地 ControlTemplate（仅 `ContentPresenter`）才彻底。
- **`VisualTreeHelper.GetParent(Run)` 会抛异常**：文档面板里的 `Run` 是 `FrameworkContentElement`、**不是 Visual**，鼠标划过就崩；上溯父级必须用 `ContentOperations.GetParent` 兜底。

### 求值 / 数据

- **ComboBox 转换器会改字面量类型**：往返后字面量从 `int` 变 `string`；unset 判断必须同时认 int / decimal / `"-1"`。
- **转换器必须返回"稳定实例"**：选中项不是集合里同一对象引用就会被清空（"选完弹回"）。转换器按「名字 + 字面量」缓存。
- **颜色取色器的 `HexCode` 是私有 setter**：只能绑 `SelectedColor`，字符串字段配双向转换器。
- **候选下拉的 ItemsSource 一律过"给下拉行做文本+图标"的转换器**：模板绑的是 `item.Text`/`item.Image`，直接喂枚举成员时每一行都是空的；样式里设了 `ItemTemplate` 时 `DisplayMemberPath` 会被它压掉，写了也没用。
- **union 分支的枚举下拉也要有（未设置）**：建支时文档里往往还没有值（分支用 null JSON 建），分支节点若只有枚举候选，镜像到 union 行上的下拉就只能显示"第一个有意义的成员"、点了也退不回去。三处一起守：① 分支节点建好后插哨兵（分支节点的"必选"没有"可选"含义，要用显式重载）；② 切支写完值要按本行的值重新派生选中项（标量分支没有子级）；③ union 行上选哨兵 = 这个键整个不存在，setter 直接转到"切到该哨兵"。
- **"必选却未选定分支"不许在建子级时挂**：那一刻子节点的"是否必选"还是默认 true（父级建完子节点之后才写），可选字段会被扣一顶假诊断而且永远清不掉。缺必填键由全树建完之后的校验统一报。
- **下拉的（未设置）哨兵必须由父级在"是否必选"落定之后插**：建子级期判"是否可选"恒为真 —— 必选字段会莫名其妙多出一个能删键的项。收口点只有"构造静态字段"与"重建节点"两处，且必须幂等。
- **`Prepare` 里读不到字段的必选性**：必选性是父级建完子节点之后才写的，`Prepare` 期间还是默认值 —— 拿它判断"必填 bool 默认 false"会把可选 bool 也落成 false（且行上假装 True 已选中）。bool 的默认值判定放到物化阶段。
- **清空语义必须走同一条出口**：数字清空 / bool 两个都取消 / 可选字符串清空 = unset（删键），必填 = 挂诊断；否则会出现"行上没了、JSON 还在"或反过来的假象。
- **成员写入按树序，不按到达顺序**：纯追加会让新键永远排到末尾，和左侧树的相对位置对不上（切枚举、补默认值、⊕ 都受影响）。
- **分页上限与"全部"冲突**：设为最大值的"全部"要绕过页大小截断；"更多"行重投影要落在**列表行**上。
- **懒建之后不能用"子级个数"判有无子级**：要问表现器"有没有能力长出子级"。
- **宽容 JSON 解析器从不抛异常**：坏文本返回部分结果，直接建树会覆盖旧树；所以"语法错误不能污染树"必须在调用处就先判。
- **建树期分支不许走值转换**（见 §三 开头的分支子树那条）。
- **建树期不能回写文本**："载入中"这个闸门不仅挡值回写，文本同步也要跳过。
- **文本相等 ≠ AST 新鲜**：编辑器里敲完字，编辑器持有的 AST 还停在上次解析，重建前必须先重解析。
- **改了参与动态索引的值必须重建，但只能延迟一拍**：同步重建会打断动态键输入（占位节点被换掉 → "加了键但 JSON 里没有"）。
- **定向重建按路径找锚点会命中"同路径的兄弟"**：动态键占位行与父容器同路径，路径索引又是子覆盖父 → 拿它重建会造出"没有键身份"的匿名条目行（文件里有、树里没有；`%key` 空 → 成员退化成 `any`）。修法：索引先写优先 + 跳过占位行、锚点本体优先、拒绝没有求值现场的节点。
- **`RefreshNode` 复用建节点那一刻捕获的类型闭包，但别往它里面加"重新求值"分支**：运行期依赖的节点早在结构变更入口就被转成"延后一拍重建"，`RefreshNode` 根本走不到。同理 `RefreshNode` 必须让路径索引失效，否则 `FindNode` 会把刚被删掉的节点捞回来、又被装回树上（"JSON 里键没了、左侧那一行却还在"）。
- **`RebuildNode` 必须把"父级写过的语义"整套带回来**：必选性 / 文档注释 / 键提示 / 条目身份（是否 map 条目、正在编辑的键、动态字段下标、键候选）/ 列表项的三颗命令 / union 显式选择 / 旧节点的展开态 —— 这些全是**父级建完子节点之后**或运行期才写的，重建只按声明类型重跑一遍会把它们全丢（现象各不相同：可选字段突然变必填、重命名与条目删除按钮当场消失、▲▼ 消失、切走的成员自己弹回去）。两条硬约束：① 命令必须按**新节点**重挂（旧闭包捕获的是已经被换掉的旧节点）；② 条目身份只在"新形态仍然成立"时回填（父级已把这个键声明成静态字段时不再是 map 条目），`⊕` 行的折叠态也不许继承给"刚长出值"的新节点。
- **摊平根的顶层节点重建必须同时换顶层集合里的那一项**：只换合成根的子级，视图还指着旧实例（子行永不更新），而"按父行重拼"又因为父行是合成根而失败 → 整表重投影。顶层区的行重拼只能按"第几个最外层行"定位（重建过的行实例已经换掉，按行对象/节点查索引会落空；按路径找又会命中同路径的占位行）。
- **`Diff` 里"对象键集合变了就整体当锚点"对根对象不成立**：根没有行可挂，只能改成"成员增删单独处理 + 公共键继续往下差分"，公共键的相对顺序一旦变了就直接回退（树序按声明序 + JSON 序，局部同步不负责重排）。根层的"新增成员"也不许进差分锚点：重建只有声明类型，拿不到建树期的语义（未声明键、动态键身份、必选性、缺必填键诊断），会把行退化成普通行而占位子行还在。

### 页面 / 宿主

- **`Console.ReadKey()` 会让被拉起的服务器秒退**：宿主是没有控制台的 WinExe，`ReadKey` 直接抛异常 —— 表现为"进程起来了但管道永远不出现"。
- **无超时的 `ConnectAsync()` 比崩溃更糟**：服务器没起时初始化永远不返回 → 骨架屏不消失、符号表为空、所有 `#[id]` 变文本框，而且一条日志都没有。
- **`Resource` 是 Prism 单例**，VM 走构造注入；初始化没跑过，任何页面都建不出树。
- **生成器页面只声明 EntryId**：所有入口页统一继承基类，页面里不许自带引擎逻辑（同步 / 默认值 / 防抖重建只有一份）。
- **入口配置文件缺了不许让整条初始化静默跳过**：这个文件不在仓里（安装包才带），旧写法第一句就是"文件存在才继续" —— 缺文件时注册表与符号表双双为空，页面变成 `null`（右侧一个 null、左侧一行、"字段 1 个顶层"，状态栏一条提示都没有，看起来像"页面载入后没有内容"）。两条一起守：① 缺文件按默认路径继续、读坏了记一条 note 一样继续；② 默认文档出口的契约是"绝不返回 null"，但缺省代数对空联合 / 没解出的指令回的是 JSON null（**不是 C# null，`??` 拦不住**），必须过"能不能物化"再退 `{}`。这个文件只承载三把旋钮：注册表目录、物品贴图根目录、入口文件（键 = EntryId、大小写不敏感；值是文件或"里面取 empty.json"的目录）；每次建默认文档都重新读，改完配置重开窗口即生效。
- **入口模板本身可能是"另一种资源"，引擎不许拿它建树**：某资源的模板文件是一份函数数组，而根声明是结构 —— 整页退化成 `any` 原始行（根显示 list、条目里全是 raw 编辑器），看着像求解/渲染坏了，其实是默认数据坏了。载入默认文档要先验根形状（结构要对象、列表/元组/原始数组要数组、any/解不开不判），不符就**退回代数默认值**并把"入口文件根形状与声明不符（期望 X，实际 Y，来自 …）"摆在状态栏。
- **`any` 行的子行与列表语义要跟着文档形状走**：借的是 struct/list 的表现器（数组项挂在 `Items` 上），但基类只看`Children`、列表语义只按类型判 —— "数组形态的 any 行"会一个条目都不出行。子级取 `Items`，并给表现器加"节点感知的列表判据"（默认跟随类型，any 按值是数组）。
- **AvalonEdit 必须用持有 `JsonTextState` 的那个编辑器**：只有它与树共用同一批 JSON 值。
- **编辑器 `Text` 不是依赖属性**：禁止在 XAML 里绑 `Text`（真机 `XamlParseException`）。
- **批量改 XAML/代码时锚点会因缩进静默失配**：替换后必须打印命中数（0 = 没改到）。

- **展平后合成根不在顶层集合里**：按路径重指碰不到它 → 顶层增删写进旧对象；"文档根"标记必须有唯一赋值点（只有"在顶层集合里且没有父级"的节点才是文档根），漏赋值时根标量编辑会走进"替换根"的拒绝分支（值只留在节点上、文档没动）。

### 验证

- **"改一个值"和"换一份文档"是两种代价，不能混着量**：整篇重排（格式化 + 整段替换 + 重解析）比改一个已存在的标量值贵一个量级以上；改一个已存在的标量值必须走"只替换那一段文本 + 只刷那一行 + 只校那一个节点"。反过来，值变成容器/多行、"可选 bool 的都不选"（那是删键）、锚点缺失、union 结构分支这四类**必须**退回整篇，硬做手术式会写坏文本。
- **投影守卫不能只看"树换代"**：局部拼接也会造出"行指向的节点不在树上"的孤儿行，而它不换树代 —— 守卫的触发键要含局部拼接/整表重投影的次数。**更硬的一条**：行与文档要按"路径 + 实例身份"对账（"还挂着"只看父链，换成上一代实例照样算挂着，抓不到），不一致就整表重投影。
- **文本非法或未消化时，树侧改动只许动模型、不许动文本**：此时锚点区间与文本已经对不上，任何"就地替换那一段"都会啃掉用户写的括号；判断依据是"有没有未消化的输入 / 上次解析是否失败"。反过来，用户一旦操作**左侧树**，就要把脏区域对齐成合法文本（否则"我点了树却什么都没发生"比改错更糟），对齐只做**容器级替换**、绝不猜字符。
- **门禁判据只能往"操作 × 契约"的矩阵里加**：一次性用例红了只会说"这条红了"，说不出破坏了哪条契约；往矩阵里加操作，失败信息才指得准（契约清单见 §2.7）。
- **断言要打 UI 路径**：直接给行模型赋值测不到真 bug（转换器会改类型）；有转换器/模板参与就必须走转换或真实控件。
- **断言不许可空过**：`if (row is not null) Check(...)` 这种写法在行消失时整条断言蒸发，必须有"找不到行 = 红"。
- **sweep 必须关闭分页与懒建**，否则"行数 == 节点数"不成立；探针与 harness 都要显式设定确定性开关（懒建 / 分页 / 延迟实化编辑器）。
- **"行数 == 节点数"要求两边吃同一份子级集合**：计数一律走表现器的"这一行有哪些子级"（union 走分支、列表走条目），并且先建子级再数；失败信息要打出第一个"建出来却没有行"的节点的路径/类型/父级状态，否则只能说"红了一批"。
- **"恰好一行"的判据要先问"这条路径本该有几行"**：未声明键自己会带一条"新键"占位子行，两者共用父级路径 —— 按路径数行会恒等于 2。判据按"有键身份的条目行"数，占位行不计。
- **门禁判据要按"身份"而不是"形状"**：map 条目的行形状恒为"键名/占位"，用"是 union 行"筛条目行永远不命中，只能靠兜底 —— 兜底让那条断言对缺陷零约束。收紧后的判据是"每个 JSON 键都有唯一且路径等于键路径的条目行"（双射）。
- **结构类操作的判据要连"代价"一起量**：文本 → 树只有一个出口（防抖 tick 与门禁共用），门禁直接调它才量得到真实工作量（不然测到的是防抖窗口）。判据是"整表重投影 = 0 次 + 模型段 ≤ 150ms"两条一起。
- **性能预算要按"修好之后真正干的活"标定**：阈值若标在"只重建 1 个节点"的错误行为上，改对之后同一条补丁要重建整片容器 —— 旧阈值就成了"用 bug 的速度给新代码设限"。预算只拦量级退化，**结构正确性另配断言**（不许整树回退 / 不牵动无关节点）。
- **现象要能复现成"一份内联文档"**：用**内联常量**把用户现场钉进门禁，比截图/口述可靠；配套的索引 trace（默认关）能把"同一层级该取哪份 JSON"直接打出来。
- **纯 `Dispatcher.Invoke` 空转不物化容器**：只认容器生成器，别拿条目数当渲染证据。
- **`Popup` 只有真实外部鼠标按下才会关**：合成事件关不掉（独立 HWND），要真点。
- **换 JSON 之后要等防抖重建**：抓行/抓节点前等"行数与文本都不再变"，否则拿到上一代行对象。
- **虚拟化复用要双判**：既比容器下标，也比"渲染文本属于本行模型"。
- **读不到"模板选择器的结果"**：要断言编辑器换没换，只能看实际物化出的控件类型。
- **绑到不存在的属性不抛异常**：只记一条绑定错误、按钮照样可见可点；靠静态守卫兜。
- **剪贴板会被人占住**：设置文本会抛"剪贴板打不开"；门禁两次尝试，都失败就记 skip 并打印原因。
- **门禁的 SKIP 会掩盖整条链**：数据快照里有、而版本下拉里没有的字段，会让整段 UI 链长期跳过（后续断言全是死代码）。要让门禁走页面自己的换版本出口直接切到快照版本，别让"环境没有"变成"验过了"。
- **原生进程必须带工作目录**：对拍脚本里用相对路径时，工作目录设错就是"找不到模块"。
- **诊断口径要能分辨"数据缺口"与"求解失败"**：声明了注册表候选却拿不到数据源（资产里没有这个注册表）算数据缺口，单独计数、不判红；"退成 any"只在**静默**降级时记 —— 已经有诊断的降级是有意的，记进去会把"非法文档的诚实降级"误判成求解失败。裸枚举的候选来自声明本身，不许在"没有注册表"时也报一条（否则每个裸枚举都计入，硬断言永远到不了 0）。
- **退出码只有三种**：绿 / 红 / 环境不足，**没有 SKIP**；"环境不足"也要能指出缺哪份数据。

## 四、与 misode 的有意偏差

| 偏差 | 原因 |
|---|---|
| 跨资源存在性只到 warn（misode checker 部分具备） | 不做 checker 级 error/自动修复：资源名/标签只做"在不在注册表"的存在性提示，语义校验（能否被引用、引用的目标合不合法）不猜 |
| 不提供 follow 跳转（misode 的 follow_reference） | 用户明确不需要跨页联动：行上的"跟随"按钮与管线里的回调、注册表→入口映射都不提供 |
| 默认展开深度 3（misode 全展开） | WPF 虚拟化下全展开=全物化，首屏直接崩 |
| 缺省字段只留一行 ⊕，不摊开子级 | 与 misode 一致；"摊开"会让删掉的结构字段把子结构留在树上（点删除像没反应） |
| 无 checker 级 Errors | C# 侧没有 spyglass checker，用结构 + 取值域校验替代；跨资源/tag 存在性不做 |
| 物品图标退化成确定性瓷砖 | 仓内 png 全是 UI 图、没有 item/block 贴图（misode 拉远端）；宁可画瓷砖也不静默空白 |
| 编辑器"延迟实化"默认关 | 摘要行更矮 → 视口物化更多容器，首屏更慢 |
| **union 行"显示即落盘"**：行上显示着某个成员、文档里却没有它的值 → 物化期按成员默认结构写进文档（用户明确要求"所见即所得，同层调度器也要跟着解"） | 不落盘就会出现"下拉选着某个成员、同层没有它的字段，切一次成员才出现"；代价是替用户写键，所以只在**显示的是具体成员**（不是未设置）时做 |
| 角标用文本字形 | 图标字典依赖 png 资源 |
| 候选外的值：不伪造候选、不显示成选中项，只挂 warn 诊断「值不在候选内：X」，JSON 与选中项都保持不动 | 判断只看"该位置有没有值"；伪造候选会把用户选择弹回去（换 trigger 后 spread 不跟就是这么踩的） |
| 白名单外 `#[id]` 也只给一件控件（单个下拉），手输自定义值走右侧 JSON 面板 | 用户明确要求"有下拉就别再放文本框"；可编辑下拉在这个控件里没有 |
| 渲染完毕后把行上显示的默认值（数字 / bool / union 标量支）落盘；**可选字段的 unset 只有编辑器一条出口，行上不再有删除按钮** | 用户明确要求"所见即所得"：右侧 JSON 必须和左侧树一致 |
| 可选字段的清空手势：文本框清空 / 数字清空 / 布尔两个都取消 / 枚举与 `#[id]` 下拉的**第 0 项「（未设置）」** / union 分支下拉的（未设置）→ **都真的把该键从文档里删掉**；可选容器与取色器没有清空手势，保留行尾的删除按钮；**当前版本不存在的键**整棵子树只出一行、不解析不给编辑器，行首是黄色 `!` + 删除按钮，行尾不再重复给 | 删键必须只有一条出口；哨兵绝不许把 `-1` 物化进文档。**例外**：union 标量镜像行的空值 = 该支的默认标量（删键会连分支身份一起删，切支立刻弹回未设置） |
| map 条目行的键以只读标签显示，改名走「重命名」入口 | 键名是用户自己起的，不该在条目行上再出现候选下拉；下拉只属于"新键"占位行 |
| 解不出来的 union 成员切过去会**回 unset**（附诊断） | 与 misode 一致：渲染不了的分支不该被"选中"，否则行上会留一个写不出合法值的编辑器 |
| i18n 中文硬编码 | CBHK 只面向中文用户 |
| 对拍白名单 14 条 | 数据里同名类型重复 + spyglass 符号碰撞；我们按"模块+文件名"解析更精确，有意不模仿 |
| 新增功能只落在"行视图 + 行模板选择器"这一套（新管线）；树控件的旧模板选择器是老管线，**只许增量** | 两套管线在仓里并存：旧模板仍被老页面使用，重构它等于把风险带进已经在跑的路径，收益只在"看着统一" |
