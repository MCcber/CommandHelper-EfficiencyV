# 词汇表：mcdoc 生成器

> 只定义**词**，不写实现、不写流程、不写文件位置。口径一旦定下就改这里，别在别处另立说法。
> 机制与踩坑见 [README.md](README.md)。

## 文档与视图

**文档（document）**
生成器正在编辑的那份数据本身。同一时刻只有一份，界面上的任何显示都是它的投影。

**视图（view）**
文档在界面上的呈现。视图不持有事实：显示与文档不一致时，错的一定是视图。

**行（row）**
视图里的一行。可能是一个字段、一个动态键、一个集合项，或一条只起说明作用的行。

**行换代（row replacement）**
同一个节点位置换一个新的行对象。行上「编辑器是哪一种」只在内容控件拿到新对象时才重新选模板，所以编辑器种类一变必须换代；种类没变就只刷表头（否则输入焦点会丢）。

**节点（node）**
文档里的一个位置，连同它在类型声明里的类型。同一位置可以被重建多次，节点对象随之换代。

**键身份（key identity）**
「父位置 + 键」构成的身份。重建前后不变，因此可以用来指认"还是那一个位置"。

**锚点（anchor）**
一次重建的落点，用键身份表示。

**默认文档 / 入口文档（entry document）**
进页面时载入的那份初始数据。来源按优先级：页面显式给的**入口文档覆盖**（一个页面服务多种入口时用，例如世界生成页按选中的生成器取各自模板）→ `Configuration.json` 的 `Generator.<EntryId>` → 按声明算出的**代数默认值**。前两种都要过「根形状与声明一致」，否则退回代数默认值。

## 求解

**求解（solve）**
把「声明类型 + 这份文档」算成「这一层有哪些字段、每个字段是什么类型」。

**范式（NF, normal form）**
求解停下时的形态：没有还等着被消去的引用、模板、映射、索引、派发。

**指令（instruction）**
求解过程中要执行的一次变换，共六类：引用、具体化、模板、映射、索引、派发。

**摊平（spread）**
把另一段结构里声明的字段并进当前这一层。摊平没做成时，字段会丢掉名字。

**映射（mapping）**
声明「某个键的取值决定另一种类型」。映射给出的是**原始类型图**，还要再求解一次才算成品。

**索引（index）**
按某个键去注册表或上下文里取值（例如方块状态）。索引的结果依赖文档本身，会随编辑变化。

**派发（dispatch）**
按某个键的取值走到不同成员。决定走哪一支的那个键叫**判别键**。

**实参 / 形参**
模板里的占位符（形参）与替换它的具体类型（实参）。替换不掉时，整支成员会算成空。

## 值域与落盘

**候选（candidate）**
行上「能选什么」的清单。候选只描述可能性，不代表已经选过。

**哨兵（unset）**
候选里的「（未设置）」，含义是「文档里没有这个键」。它没有对应的值，不能当值写进文档。

**必选 / 可选**
可选字段在文档里缺席是合法的；必选字段缺席是缺陷。

**物化（materialize）**
把「必须有值、但文档里还没写」的字段写进文档。

**不动点（fixed point）**
一轮物化没有再写出任何东西的状态。物化必须跑到不动点——先造出容器，容器里的必填字段才有位置可写。

**懒建（lazy children）**
可选且没有值的字段先不建子级；它的子树到展开时才出现。

**保留区（preserved group）**
当前版本 schema 里不存在的键（版本更迭后的遗留数据）集中挂在的那个合成容器，标题写成「当前版本不存在（N）」。它不在文档树里、不占任何真实路径，默认收起；值原样留在 JSON 里，导出会带上，删除只能一个一个删或整片清空。

## 结构与验证

**诊断（diagnostic）**
文档自身就能判定的结构问题：必填缺键、未知字段、类型不匹配、未解析引用、长度越界。语义问题不在此列。

**判别键宿主（discriminator host）**
判别键要被预写进文档时，先要在 `DeclaredType` 上找到"这一层的结构是哪个"：union 里只有**能原样装下 JSON 现有键**的成员才配当宿主（带 spread 或动态键字段的成员什么键都能接，证明不了形状）。找不到精确宿主才退回"第一个结构成员"。

**版本（version）**
同一份声明在不同游戏版本间可能不同。版本是横切维度：它换的是整棵类型图，不参与任何局部路径。

**契约（contract）**
两个视图必须同时成立的性质（例如「行上显示某成员 ⇔ 文档里有键」）。契约被推翻要先改契约，再改代码。

**门禁（gate）**
一条可执行断言，代表一个不该被悄悄推翻的契约。
**快路径（fast path）**
文本编辑能被差量消化、不必整树重建的那条路：值补丁就地改节点、锚点只重建受影响的子树。判据是 `McdocSyncStats.Fallback == false`。

**定向写回（splice）**
模型 → 编辑器的写回：只替换公共前后缀之间那一段（`ReplaceRegion`），脏区间外的文本与锚点原地不动，光标一次算术落位。判据是 `WholeWriteCount` 不涨、`SpliceCount` 涨一次。

**子树写回（subtree splice）**
结构编辑的写回通道：只给「离脏节点最近的仍有锚点的祖先」出一段局部文本（`McdocJsonFormatter.FormatAt`），在该节点的文本区间里做一次公共前后缀裁剪后拼接，区间外的锚点一个都不动。判据是 `WholeWriteCount` 不涨而 `SpliceCount` 涨、脏区间远小于全文；前置条件（同根 / 同代 / 锚点可信）不成立时退回整篇排版。

**条目级写回（item splice）**
列表尾部增删一条时的写回通道：`JsonTextState.SpliceItemInsert` 在最后一条的锚点之后插 `,\n<缩进><这一条的排版>`，`SpliceItemDelete` 用被删条目的锚点定位、从闭合括号往回确认「它就是最后一条」后连同前面的逗号一起抹掉。前置条件是子树写回那套守卫再加一条「新条目还没有锚点、再前一条有锚点」。删掉的条目模型里已经没有了，靠 `McdocTreeNode.TextRemovedItem` 把锚点带过来；不满足就退回子树写回（仍是子树级，不整篇）。

**条目操作 / 单键操作（item op / member op）**
`McdocSyncEngine` 下沉到结构层的两种细粒度操作：数组**尾部**增删一条（`ItemOps`）与任意结构容器增删**一个键**（`MemberOps`）。中间插删与键序变化不在其列（`JsonPath` 会整体挪位，仍整段当锚点）。op 与锚点各受 `MaxAnchors = 20` 约束，不合计。

**细粒度退化（fine-grained degrade）**
单个 item/member op 走不下去时的出口：只把**该容器自己**记成锚点并写 `FallbackReason = 细粒度退化 …`，不整篇回落。只有锚点预算或覆盖判据不满足才退回整篇重建。

**整篇接管（whole write）**
换一代文本（`Reload` / 页面载入）的唯一出口：物理写回同样只动真正变过的那一段，但随后全文重解析、Root 换成文本里的那棵树、锚点整表重建。计数 `WholeWriteCount`，门禁断言「树侧编辑一次都不涨」。

**回落（fallback）**
放弃差量、改用整篇重建的那条路。每条回落都必须带 `FallbackReason`（出口名 + 计数），不许静默命中。

**锚点（anchor）**
文本侧同步里「形状变了的最小容器路径」。锚点内的子树整体重建，锚点外原样保留。锚点过多（超过 20 个或超过已建节点数的 30%）时整篇回落。
另一层意思：写回时的文本坐标 —— `TextAnchor` 是唯一真相，`Spans` 只是按需折算的派生视图。

**未建节点（unbuilt node）**
懒建树下还没长出来的节点。值补丁落到它的路径上只计数（`UnbuiltPatches`）不回落：树上没有行要刷新，重指之后展开时按新 AST 建树。

**消化（digest）**
把编辑器文本吃进树的过程。编辑器有焦点时只校验语法、推迟到失焦或 60ms 补跑，避免「每敲一个字符丢焦点」。

**同步阶段（sync phase）**
文本通道此刻的状态：`Idle / Digesting / Rebuilding / Deferred / Pushing`。由既有布尔闸门只读派生，不参与判定，只用于状态栏与打点。

**代际（generation）**
AST 与文本的一次配对。两者必须同代；换 AST 的载入不换文本状态实例，整篇写回只有一个执行者。注意 `McdocTreeDocument.Generation` 在 `Load` 与 `AdoptRoot` 里都会自增，**不能**当「是否整篇重建」的判据。
